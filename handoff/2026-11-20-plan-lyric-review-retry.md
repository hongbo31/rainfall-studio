# 计划中心作词评分与继续优化

2026-11-20

后续适用的目标评分与历史恢复方式见 [AI 作词目标评分与最高分稿](2026-11-20-lyric-target-score.md)。

## 故障原因

- 「测试」计划的作词任务 `d4eab6ad-d126-43ec-b0d1-1fc95fc2e2ea` 已生成《旧票根》。初稿和 5 轮改写依次得分 78、78、72、72、78、72。未达到 95 分的通过线，第一首歌停在作词阶段，尚未提交谱乐生成。
- 评语提到断句、重音、韵脚和叙事推进。旧版评分与改写请求缺少原始创作简报，其中部分建议把台湾苦情曲风理解成台语演唱要求，原模板要求普通话和简体中文。

## 改动与影响

- `src/core/lyric-writing.ts` 在计划的带歌词任务中，将原始灵感、艺人信息和模板随评分及改写请求发送。评分分开核对曲风与语种，改写选取已评审的最佳稿。仍需取得至少 95 分且通过语种校验才会提交音乐生成。
- `src/core/plan-workflow.ts` 在用户明确重试已用尽改写次数的同一项时，核对原执行项、任务、模型版本和创作简报，接续原最佳稿。重试独立计费，历史稿件、评分与费用保留。继续优化沿用原计划的单轮改写上限和已有的重试次数限制。
- `src/renderer/pages/PlanCenter.tsx`、`src/renderer/components/PlanLyricReview.tsx` 和 `src/renderer/plan-center.css` 提供「查看作词评分」和「继续优化（按服务计费）」。评分折叠区显示通过线、已用改写次数、各稿评分和扣分意见。浏览器和 Windows 客户端共用这些界面与执行逻辑。
- 回归覆盖在 `tests/plan-workflow-refactor.test.mjs` 和 `tests/plan-workflow-ui.test.mjs`。

## 验证

- 以只读方式读取实际任务，将所需记录放入内存 SQLite。无头 Chromium 加载经 `Start-Rainfall-Browser.bat -BuildOnly` 构建的界面，在「测试」的执行详情中可展开历史评分。点击重试后，隔离执行器从 78 分稿进入改写，请求包含原普通话和简体中文要求，原历史记录完整。
- 基础、AI 作词和计划工作流共 44 项自动测试通过，包含核心与无头界面。离线模型夹具证明低分稿会留在作词阶段，达标稿按正确字段流向音乐生成。TypeScript 检查及浏览器、Windows Main、预加载和 Core 的共享构建通过。
- 本轮只执行后台验证。真实文本 API、音乐生成及 Windows 原生窗口待验收。

## 恢复与回退

- 用原来的 `Start-Rainfall-Browser.bat` 启动浏览器工作台，在「计划中心 → 测试 → 详情」打开北京时间 11 月 20 日 18:36 的执行，再点该作词阶段的「继续优化（按服务计费）」。本次继续优化最多调用文本 API 10 次，达到通过线后由计划继续执行。
- 数据库沿用现有结构。需要回退时，先暂停有关执行，再用原可用构建和对应备份在隔离库验证。桌面入口按现行验收流程切换。
