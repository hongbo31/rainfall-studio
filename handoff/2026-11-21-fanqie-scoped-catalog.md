# 番茄目录上传按本批查询

旧版目录上传进入表单前会打开「成品发行」，从第一页扫描整个账号。截图中的 28,756 条历史作品对应 2,876 页。两次失败均停在目录读取，本批歌曲保留在待处理队列。

## 改动

- 目录上传一直使用已登录的番茄账号。预检和最终确认前只查询当前候选或选中的歌曲，按完整歌名识别同名，继续使用本地录音指纹和投稿记录拦截重复上传。
- 使用官网作品列表的只读查询。在账号核对页按歌名或作品 ID 请求结果，查重与回执读取均从这里完成。需要续办已有合同时，用官网搜索框定位对应作品。两处都省去了网页分页。查询范围超过可核验的 100 条匹配结果时暂停，以便发现异常的未筛选返回。
- 点击官网「确认上传」后，短时间内只按本批歌名等候新增回执。已有作品 ID 的核对使用对应歌名及 ID。合同准备同样限定在本批，最后签署仍由本人确认。
- 执行日志使用 `catalog:batch-lookup` 标出本批查询步骤。查询失败、登录失效或结果超出范围时，会保留执行状态和可用的截图诊断。账号管理的完整作品报告仍使用原有读取方式。

## 涉及文件

- `src/main/fanqie/catalog-lookup.ts` 和 `src/shared/fanqie-catalog.ts` 实现筛选范围、响应校验、完整 ID 和查重。
- `src/main/fanqie/catalog-session.ts`、`directory-run.ts`、`authorize-records.ts` 和 `src/shared/fanqie-downloads.ts` 接入上传、续跑、回执、合同准备和失败状态。
- `tests/fanqie-directory-catalog.test.mjs`、`tests/fanqie-downloads.test.mjs` 和 `tests/fanqie-authorization.test.mjs` 覆盖大目录、重传防护和合同范围。

## 验证与回退

143 项相关测试通过。28,756 条历史记录的无头测试覆盖异常查询暂停、按歌名恢复、跳过历史同名、填写并提交上传表单一次、等待延迟回执、保存完整作品 ID，以及关闭临时核对页。TypeScript 检查、原浏览器入口构建和 Windows Electron 本地桥接验证通过。实际番茄账号上传及 Windows 原生窗口待验收。

可用原浏览器入口加载该版本。回退时恢复本次改动的源码和测试，保留作品库、现有目录队列与上传回执。回退后的目录上传会恢复全库查重。
