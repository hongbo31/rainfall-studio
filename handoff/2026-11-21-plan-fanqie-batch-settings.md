# 计划中心番茄音乐的分批和签约设置

2026-11-21

## 原因和操作

计划中心的发布节点原来只保存番茄发布账号及核对结果。「每批上传上限」「是否签约」原先由平台管理的「目录上传」面板配置。

点击计划工作流程的「番茄音乐」卡片，在节点配置内可选择账号、查看和修改每批上传上限与签约选项。已有计划设置优先带入，新设置从选中账号的目录上传默认值带入。填写后保存计划。已连线的生成发布流程使用连入该节点的作品。独立番茄节点的目录上传见 [交接记录](2026-11-21-plan-fanqie-directory.md)。

## 执行与兼容性

- 每批按保存的上限划分。前一批取得对应回执后，队列才领取下一批。选「是」时读取已进入审核或已上架的签署后回执。选「否」时，官网核对到本批作品的同一份待签合同即可继续。由本人在番茄官网确认生成合同，签署也由本人在官网完成。待签合同和已投稿结果分别记录。
- 发布中心任务明确设置「是否签署合同」时，任务选项决定合同步骤。旧计划和既有执行可按原有快照读取。账号、官网作品 ID 和歌名用于精确核对，继续使用已有上传回执和去重规则。

## 涉及文件

- `src/renderer/components/FanqieBatchFields.tsx`、`FanqieDownloadUpload.tsx` 和 `PlanWorkflowForm.tsx` 共用两项配置的控件及校验。 `src/renderer/pages/PlanCenter.tsx` 在执行确认时显示已保存的选项。
- `src/shared/plan-center.ts` 将番茄批次设置写入计划节点和执行快照。 `src/core/publication-queue.ts`、`plan-fanqie.ts` 和 `plan-workflow-publication.ts` 负责分批、领取顺序和合同回执。 `src/main/fanqie/plan-publisher.ts` 与 `src/main/bootstrap.ts` 通过所选账号核对原作品。 `src/shared/fanqie-catalog.ts` 从回执中识别待签合同编号。

## 验证与回退

- 在隔离库通过 70 项回归，覆盖计划节点读取账号默认值、保存回显、无效上限、单首分批、两种续跑条件及错配回执拦截，以及既有目录上传和发布任务。浏览器界面使用无头夹具，Windows Main、预加载、Core 及共用渲染层通过构建与 TypeScript 检查。
- Windows 原生窗口、正式账号投稿及本人签署待验收。回退时备份计划和回执，撤回本轮源码与测试，用改动前的计划数据副本试跑旧版。保留作品和官网回执供核对。
