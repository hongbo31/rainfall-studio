# 番茄目录上传共用流程与查重重试

## 证据与原因

最新计划运行先读取账号成功，再在 `catalog:batch-lookup` 阶段发生 `FANQIE_CATALOG_LOOKUP_FAILED`。trace 已保留底层异常 `TypeError: Failed to fetch`，失败发生于歌曲表单打开前，说明是番茄官网只读作品查询请求的网络失败。

平台管理的“执行上传”和计划中心的本地目录计划均使用同一 `FanqieDirectoryRun`，共用批次启动、歌曲表单、投稿回执与后续清理逻辑。计划入口另外检查计划状态、配置快照，并采用计划保存的批次参数；并不存在两套歌曲上传表单流程。

## 改动

- `src/main/fanqie/catalog-lookup.ts` 对共用作品查重请求增加最多 3 次尝试，仅网络失败及 HTTP 5xx 会重试，每次短暂退避。登录失效、参数错误及其他确定性错误保持立即失败。
- 既有诊断改动继续记录底层 fetch 错误或 HTTP 状态，供两入口共享的目录执行日志定位。
- `src/main/fanqie/directory-page.ts` 的新页面尝试已撤销，继续复用安全起始页面，以保留番茄登录会话。

## 验证与边界

- 尚未使用真实账号复跑，未运行测试。新增重试仍需通过浏览器候选构建检查。
- 该改动覆盖两个目录上传入口的共用查重请求。若网络持续失败三次，任务仍会失败并保留最终网络原因。

## 回退

撤回 `src/main/fanqie/catalog-lookup.ts` 中 `readPage` 的三次有限重试即可恢复单次请求行为。此前的错误原因记录不需要随之撤回。
