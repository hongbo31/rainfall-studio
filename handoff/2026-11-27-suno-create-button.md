# 2026-11-27 苏诺之音创作按钮适配

## 排查依据

用户提供的页面 DOM 中，苏诺自定义模式创作按钮的可访问名称是「创作2首 · 10」。此前自动化只匹配「创作」以及紧跟分隔符的名称，在此页面定位不到按钮，提交前会报 `SUNO_CN_SUBMIT_UNAVAILABLE`。本次没有读取真实任务日志，不能由页面快照确定历史失败的具体原因。

所给页面的歌名输入框、风格输入框、纯音乐开关、作品列表、更多菜单和「下载wav音频」与现有定位规则匹配。页面快照处于纯音乐模式，歌词、人声及音色控件在该快照中未展示。

## 修改

- `src/main/suno-cn-browser-page.ts` 允许创作按钮名称包含「2首」及积分信息。现有按钮可用性试点、一次提交、结果确认、两首 WAV 验证和归档流程沿用。
- `tests/fixtures/suno-cn-browser.html` 模拟当前按钮、初始纯音乐状态，以及菜单直接开始浏览器下载的页面行为。没有保存用户提交的页面或账号数据。
- `tests/suno-cn-browser.test.mjs` 覆盖人声、纯音乐、两种 WAV 下载路径和非两首按钮不提交。测试替身的歌词校验等待时限设为 150 毫秒，实际运行继续采用既有时限。

## 验证

- 用户所贴 DOM 在离线解析环境中核对，原创作按钮规则匹配数为 0，修改后的匹配数为 1。作品菜单及 WAV 文案的定位规则在该页面快照中各匹配一个目标。
- 隔离无头浏览器回归中，新按钮的人声、纯音乐、非两首阻断、旧按钮及原 WAV 菜单测试通过。菜单直接触发浏览器下载的独立模拟测试通过，并校验 A/B 音频、歌词和封面归档。
- 完整苏诺回归在新增直接下载测试之前为 28/30 通过，两个失败均为封面提示词断言。使用修改前的苏诺页面源码复测，两个用例仍以相同断言失败，涉及既有的标点清理行为。
- `Start-Rainfall-Browser.bat -BuildOnly` 构建共享 Main、preload、Core 和页面成功。浏览器与 Windows 客户端共用 Main 侧实现，当前运行中的进程使用原有源码快照。
- 未运行真实生成、官网 WAV 下载或 Windows 原生窗口验收。本机没有 `verified-desktop.json`，已安装客户端入口未更新。

## 回退

只撤销 `src/main/suno-cn-browser-page.ts` 中创作按钮匹配规则、上述对应测试和本交接条目，再用同一浏览器入口构建。保留历史任务、作品和账号配置。
