# RF-019 决策单：任务中心与计划中心异常处理

决策依据｜2026-11-24（北京时间）｜**用户连续回复“继续”后，按此前说明的推荐默认推进实现**

## 当前采用的默认

| 项目 | 本轮执行口径 |
| --- | --- |
| 同计划跨入口并发 | 同一 plan 只允许一个 active run，Core 事务原子拦截；让第二入口查看现有 run。 |
| 作词 usage unknown | 保留 reservation，阻断耗费型下游；已有逻辑核实后不重复实现。 |
| 核对与重试 | unknown / not_found 不自动重试；not_found 不当作未发送证明；核对追加保存，明确 failed 才能按现有重试资格重试。 |
| 等待阈值 | 不虚设数值；继续显示耗时和本地更新时间，不自动取消、失败或重发。 |

上述口径于 2026-11-24 按 susu 在本线程连续回复“继续”确认采用。下方决策矩阵保留确认前的实现现状和备选项，供追溯，不再表示等待决策。

本轮实现和未完成边界见[实施交接](2026-11-24-rf019-safe-concurrency-reconciliation.md)。

| 决策 | 决策确认前现状 | 已采用默认 | 当时可选替代 | 影响与验收重点 |
| --- | --- | --- | --- | --- |
| **1. 同计划跨入口并发** | `PlanCenter.hasActiveRun(planId, source)` 按 source 是否为 `publication_task` 分组检查活跃运行。同计划可同时存在“任务启动”和“计划/手动/定时启动”的运行；同组则拒绝重复启动并报 `ACTIVE_RUN`。见 `src/core/plan-center/index.ts`。 | **禁止同一 plan 同时存在多个 active run**，不论从哪个入口启动。第二入口直接定位现有 run，显示 owner/source。服务端原子检查为准。 | 保留跨入口并行：每个 run 明示来源和独立范围；需保证不同 run 不重复使用相同作品/发布目标。 | 禁止并发可防止重复扣费、生成和投稿，但改变当前跨 source 可并发行为，**须 susu 决策**。验收：并发点击/竞争请求最多创建一个 active run，另一入口可打开它；若批准并发，必须证明隔离范围且 UI 不混淆回执。 |
| **2. 作词 usage unknown 但已有内容** | `lyric-writing.record()` 在费用无法核实或 provider outcome unknown 时保留 `unknown` 和 reservation；`tickPlanLyrics()` 读取该作词 job，但未知时不会把它当成功进入下一阶段。见 `src/core/lyric-writing.ts`、`src/core/plan-workflow.ts`。 | **阻断后续所有耗费型阶段**（评分、改写、音乐生成）；展示“歌词内容可查看，调用用量待核对”，保留 reservation。 | 允许用户在预算上限/付费确认后显式继续；内容、usage、reservation 仍分别展示，并记录授权。 | 阻断更能避免无法对账时继续产生费用，可能增加等待。正文可用不等于费用已核实。是否允许付费继续，**须 susu 决策**。验收：unknown 不推进；内容和余额状态分别显示；获批替代必须有金额上限、确认记录和审计。 |
| **3. `unknown` / `not_found` 对账与重试** | `PlanCenter.reconcile()` 会把当前 attempt 改成 `pending`/`not_found`/`succeeded`/`failed`，没有独立追加 observation 历史；`not_found` 当前可进入 `retry()`，而 `unknown` 通常被拒绝。provider 作词另有仅在本地 job 为 ready 且无 operation 的严格 `resumeUnsentProviderGeneration()`。见 `src/core/plan-center/index.ts`。 | **未知状态不自动重试；`not_found` 只表示本次核对未找到，不自动等于未发送/无副作用。人工核对追加证据、操作者、时间和结论；原 attempt 保留。** 未证明无副作用或可靠幂等时禁重试。 | 对明确有供应商幂等保证或可证明未发送的请求，允许人工精确重试单个 `item + stage`；自动重试可另行限定在同等可证场景。 | 安全性最高，但可能需要人工处理。是否允许人工/自动重试及证据标准，**须 susu 决策**。验收：unknown 不可盲重放；`not_found` 不自动变“未发送”；核对记录追加且不覆盖原 attempt；批准重试时服务端校验幂等/证据、精确范围，已成功阶段不重跑。 |
| **4. 等待阈值与升级** | Plan Center 诊断可显示距阶段开始的耗时；代码未见适用于所有阶段的统一等待升级阈值。UI 约 4 秒轮询只是状态读取频率，不能当作服务端超时。见 `src/renderer/pages/PlanCenter.tsx`、`src/renderer/use-center-query.ts`。 | **先展示 elapsed、last checked、当前阶段和已有外部 ID；超过提示阈值只提醒“等待较久/建议核对”，不自动取消、改成失败或重发。** 阈值按阶段取运行数据后再定。 | 按阶段设置明确期限，超期转为“需用户处理/阻塞”，由用户核对后恢复；依然不自动重发。 | 提醒不改变副作用，容易先落地；阻塞升级可减少无限等待但可能过早打断正常慢任务。阈值数值、提醒或阻塞升级，**须 susu 决策**，并以实际阶段延迟证据设值。验收：轮询频率不触发超时；展示派发时间/最近核对/耗时；升级不撤回外部请求、不触发重试。 |
