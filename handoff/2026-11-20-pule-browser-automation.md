# 平台管理的谱乐 AI 自动制作

2026-11-20

## 使用

在「账号管理 → 谱乐 AI」添加各个账号。先在「配置中心」设置下载目录，并选择支持自动出图的默认封面来源、保存该接口的 API 密钥。在「平台管理 → 歌曲生成」，谱乐 AI 卡片右上角的「打开页面」可核对所选账号的登录状态。点击卡片或「执行」打开右侧面板，选择谱乐账号和艺人，填写歌名、歌词和音乐风格，或开启「纯音乐」。点击「开始制作」时核对目录和封面配置，再打开该账号的专属浏览器窗口。已开启的专属窗口可直接复用。需要重新登录时，在同一个制作页完成登录后自动继续。

翻唱在点击「开始制作」前选择有权上传的音频，版权音频处理前在底部「执行记录」中确认官网报价。普通制作与翻唱的歌曲生成均直接提交。谱乐用 A 版歌名生成两首。若填写了 B 版歌名，任务先在谱乐修改第二首的歌名。每版依次下载 WAV、保存歌词 TXT、调用默认封面接口并保存 PNG。纯音乐保存 WAV 和封面。「执行记录」可查看各版已保存的文件及目录。

## 自动制作流程

1. **校验下载目录、封面接口并打开制作页。** 读取配置中心已保存的下载目录，核对实际目录的身份。未选择目录返回 `DOWNLOAD_ROOT_REQUIRED`。同时固定本次的下载账号与默认封面接口，优先读取下载账号下匹配艺人的 A/B 歌手和提示词引擎。预查接口的 API 密钥是否已保存。通过后根据谱乐账号 ID 打开专属窗口的 `/create`。有现成的账号页时，在同一窗口开独立制作页，继承账号会话。
2. **核对登录。** 等待侧栏账号和「自定义模式」加载，再点击该模式。侧栏已有已登录账号时关闭误开的登录框。遇到「登录领取积分」就点弹窗内的「关闭」。确需登录时打开官网登录框，最多等待 10 分钟，成功后继续原任务。
3. **上传翻唱音频。** 翻唱依次点击「上传音频」「版权歌曲上传」「选择音频文件」，用 Playwright 的文件选择事件设置已选音频，再点「保存」。确认「开始处理」显示的报价后提交，等「版权歌曲上传中」消失并识别到本次新增的「翻唱此歌曲」，再点击它。普通制作直接进入表单。
4. **填写创作表单。** 按输入设置「纯音乐」。带歌词时根据艺人的共用配置选音色并点「使用此音色」，填写标题、歌词、音乐风格，选择歌手性别。纯音乐填写标题和风格。表单控件最多等待 45 秒，各项填写或选择后等待页面更新，再核对文本或选中状态。
5. **记录制作前的第一首。** 提交前，从 `#music-list ul.w-full > li` 按 DOM 顺序取第一行歌名，并记录当前页歌曲 ID。第一行歌名来自行内的 `div[1]/div[2]/div[1]/a`。第一次制作时允许官网明确显示的空列表。榜首和空列表都无法确认时，以 `PULE_RESULT_BASELINE_UNAVAILABLE` 停止提交。
6. **准备归档目录并提交。** 提交前在下载根目录直接检查 `账号名称_A版歌手_提示词引擎` 和 `账号名称_B版歌手_提示词引擎`。已有目录通过校验后直接复用，仅在缺失时创建。两版的目录名一致时共用同一目录。点击 `#creation-area` 下 `div/div[2]/div/div[2]/div/button` 中的「立即制作」。遇到「每次生成模型都会同时生成两首歌曲以供选择」时，在该提示框内点击一次「确定」。从最后一次提交或确认起等待至少 8 秒，并等到 `//span[text()="生成中"]` 不可见。
7. **断言榜首并锁定两首。** 第一行的歌名必须和提交前不同。第一、第二行还须都是本次新增的曲目，且初始标题等于提交的 A 版歌名。前后榜首同名时记录 `PULE_FIRST_TITLE_UNCHANGED`，无法确认两条新歌时记录 `PULE_RESULT_UNCLEAR`。核对通过后将第一、第二行的 ID 按 A、B 顺序写入任务记录。ID 来自歌曲链接或行上的 `data-song-id`。
8. **保存 B 版歌名。** 点击第二首行内 `div[2]/button` 的「更多」，把 `//span[text()="修改歌名"]` 滚入视口后点击。在「修改歌名」弹窗核对「新歌名」输入框中的原名，填写 B 版歌名并点击弹窗内的 `//button[text()="保存"]`。等弹窗关闭且同一歌曲 ID 在列表中显示新名字后再下载。B 版歌名留空或和原名相同时跳过改名。
9. **打开 A 的 WAV 弹窗并检查重试。** 按歌曲 ID 和歌名点击行内 `div[2]/button` 的「更多」，再点 `//span[text()="下载 WAV 音频"]`。从该点击起等 2 秒，优先检查 `//section[@role="dialog"]//button[contains(., "重试")]`。发现按钮就点一次，每首最多 3 次，每次点击后再等 2 秒检查结果。
10. **保存 WAV 和歌词。** 等到 `//section[@role="dialog"]//button[contains(., "下载文件")]` 出现后，先监听 Playwright 下载事件，再点该按钮。等待弹窗和下载事件的超时各为 5 分钟。WAV 下载完成后校验文件头，写入对应歌手目录，带歌词的歌曲同时保存 UTF-8 同名 TXT。
11. **为已下载版本生成封面。** WAV 保存后调用配置中心选择的默认封面接口。使用该版歌名、歌手、音乐风格和歌词生成简短描述。智谱请求使用其默认方形尺寸，收到图片后按艺人配置的目标分辨率转存。PNG 路径直接由已保存 WAV 的完整路径改扩展名得到，保留歌手目录、文件名和重名编号。A 版出图流程结束后清理其弹窗，再用第二首的 ID 重新执行步骤 9 至 11。两版处理结束后关闭制作页。[智谱图像生成接口](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E5%9B%BE%E5%83%8F%E7%94%9F%E6%88%90)
12. **记录异常和中断。** 重试 3 次后仍出现「重试」时记录 `PULE_DOWNLOAD_RETRIES_EXHAUSTED`。WAV 弹窗不可用和下载超时分别用 `PULE_DOWNLOAD_CONFIRM_UNAVAILABLE` 和 `PULE_DOWNLOAD_TIMEOUT`。封面请求在调用前写入任务记录，接口拒绝时记录 HTTP 状态。A 封面失败时继续处理 B，已落盘的 WAV、TXT 和 PNG 保留，出错任务显示「待核对」。封面失败或结果未知时不会自动重发同一版。

## 封面未落盘排查

浏览器预览最近一次任务的日志记录两版均发起智谱请求，最终是 `PULE_COVER_GENERATION_FAILED`，属于封面保存前的失败。旧记录没有保留具体 HTTP 状态。实际任务所用歌词与音乐风格拼接后的描述比此前成功出图的描述长。本轮在谱乐流程中压缩封面描述，继续完整保存用户提交的歌词 TXT，使用出图接口支持的默认方形尺寸和本地目标分辨率。新任务从实际 WAV 完整路径取 PNG 目标，既有任务记录可继续读取。

## 改名与下载相关文件

- `src/main/pule-browser-page.ts` 按歌曲 ID 重新定位对应行，管理 WAV 弹窗的「重试」「下载文件」以及 A、B 的处理顺序。官网更新歌曲列表时核对 `songTitlePath`、`songMorePath` 和下载弹窗。
- `src/core/index.ts` 和 `src/core/download-archive.ts` 在制作指定发布账号时，用该账号和所选艺人的 A/B 歌手、提示词引擎命名目录。沿用默认归档设置时，目录前缀依次采用已保存的下载账号、唯一的默认发布账号、默认番茄账号、本次谱乐账号。按 A 版歌手匹配归档账号下的艺人，候选重复时用已关联的引擎和艺人名称确定对应资料。没有唯一匹配时沿用本次选中的艺人。引擎未关联时使用「未关联提示词」。
- `src/main/pule-browser.ts` 仅创建不存在的目录，按路径核对目录身份。保存 WAV 和 UTF-8 歌词，复用 `src/main/api-credentials.ts` 的生图接口并写入 PNG。提示词来自 `src/shared/cover-handoff.ts`，与封面工作室的默认提示词共用。浏览器版和 Windows 客户端由 `src/main/bootstrap.ts` 调用同一流程。
- `src/shared/pule-browser.ts` 记录已发出的各版封面请求和两个落盘目录，保留旧任务读取。`src/renderer/components/PuleBrowserGeneration.tsx` 显示下载、封面进度及两版目录。单元和无头回归分别使用 `tests/download-archive.test.mjs`、`tests/pule-browser.test.mjs` 和 `tests/platform-management-ui.test.mjs`。

## 登录状态修复

2026-11-20 的浏览器预览任务记录中，两次 `PULE_LOGIN_REQUIRED` 分别发生在打开创作页和填写表单阶段，两次均未走到扣积分。原先账号管理的「登录待核对」来自已保存的浏览器配置。制作流程看到创作控件后会立刻开始，把短暂出现的登录控件和页面其他位置的「立即登录」误判为退出。

- `src/main/pule-session.ts` 提供两处共用的官网登录检查，依据谱乐侧栏账号控件、官方登录框和登录页。账号信息还在加载或页面无法核对时保留待核对状态。制作开始前等待官网显示当前账号，填表时短暂的账号状态切换也会等待恢复。
- `src/main/browser-accounts.ts` 从当前账号已有的登录标签页打开独立制作页，由 Chromium 继承该标签页内的会话。任务关闭制作页后，用户原来的账号页仍可继续使用。
- `src/main/bootstrap.ts`、`src/shared/pule-browser.ts` 和 `src/renderer/pages/PlatformAccounts.tsx` 把同一官网状态显示在账号管理。窗口打开期间自动刷新，可显示「登录有效」「请在窗口登录」和「登录待核对」。`src/renderer/components/PuleBrowserGeneration.tsx` 将历史任务提示限定在当次制作。
- `tests/pule-browser.test.mjs`、`tests/fixtures/pule-browser.html` 和 `tests/platform-management-ui.test.mjs` 覆盖账号延迟加载、表单阶段短暂变更、无关登录按钮、制作页继承会话和账号管理状态刷新。修改前复现了 `PULE_LOGIN_REQUIRED`，修改后 30 项定向回归及隔离 Windows 构建通过。匿名无头实站验证了官网登录框，账号已登录的续跑使用隔离夹具。真实账号前台验收待完成。[谱乐 AI 创作页](https://app.yourmusic.fun/create)
- 回退时撤回本节所列的登录检查、会话继承、状态文案和测试改动后重新构建。任务记录继续按既有格式读取。

## 多账号制作

- `src/renderer/pages/PlatformAccounts.tsx` 的谱乐 AI 页面显示账号列表、添加账号、专属登录窗口和会话状态。艺人资料仍可在发布平台账号下管理。添加谱乐账号后即可登录，旧谱乐账号的艺人资料保留并可用于制作。
- `src/renderer/components/PuleBrowserGeneration.tsx` 从本地艺人库取选项，默认优先选择发布账号下的艺人。同名艺人标注所属账号。指定发布平台和账号时，从该发布账号下选艺人。切换谱乐账号时保留艺人选择和表单资料。`src/core/index.ts` 分别校验谱乐账号和艺人 ID。制作读取所选艺人的共用性别、音色和 A/B 歌手。
- 第一项任务启动后，可在面板切换至另一谱乐账号并点击「开始制作」。`src/main/browser-accounts.ts` 按账号 ID 隔离持久化浏览器配置，制作页只继承所选账号的会话。`src/main/pule-browser.ts` 按账号限制每个账号同时运行一项制作。同一归档目录出现同名歌曲时，WAV、TXT 和 PNG 统一加重名编号。
- 回退本轮时撤回账号页、制作表单及 Core 艺人校验的改动与对应测试，再重新构建。账号、艺人和任务沿用已有存储格式。

## 实现与影响

- 每版文件直接保存到下载根目录下的「账号名称_该版歌手_提示词引擎」。本地浏览器预览的旧任务用「素素谱乐」下缺少 B 版歌手的资料取名，得到了「素素_陈白狐_6080国语苦情女歌手_B」。新版读取「素素」下的同一艺人，核对为 `素素_陈白狐_6080国语苦情女歌手` 和 `素素_陈天狐_6080国语苦情女歌手`。
- 两版的目录名相同时共用该目录，文件上的 `- A` 和 `- B` 区分版本。WAV、TXT、PNG 使用同一个文件名主体，如 `夜灯 - B`。复用目录时如已有同名文件，给本次三份材料统一加 ` (2)` 等顺序后缀，保留先前的文件。任务固定启动时读取的目录和配置，旧任务按记录的原路径查看。
- `src/shared/pule-browser.ts` 和 `src/shared/schemas.ts` 定义可信应用桥接的 `puleBrowser.start` 输入。调用方可传入 `title`、`lyrics`、`style`、`alternateTitle`、`instrumental`、所选的谱乐账号 ID 和艺人 ID、制作方式及请求 ID。翻唱使用 `puleBrowser.chooseAudio` 返回的文件令牌和上传授权。
- `src/core/index.ts` 和 `src/core/download-archive.ts` 校验所选账号、艺人及已配置下载目录的身份。Playwright 从艺人资料读取共用音色和性别。纯音乐启用官网开关后跳过歌唱设置。
- `src/main/bootstrap.ts` 和 `src/main/browser-accounts.ts` 通过谱乐账号 ID 取得专属浏览器配置。制作在前台 Chromium 标签页运行。任务结束时关闭制作页，由任务新开的专属窗口也随任务关闭。
- `src/main/pule-browser-page.ts` 识别官网登录状态并打开官方登录框。登录等待最长 10 分钟。版权音频处理提交前重核该步骤的报价。普通生成和翻唱均按本次新增的曲目 ID 绑定 A/B，等待生成状态结束后逐份保存 WAV。
- `src/main/pule-browser.ts` 在当前数据根的 `runtime/pule-browser-jobs` 记录制作阶段、积分确认、两首曲目 ID 和文件去向。关闭制作页会终止任务及待确认报价。中断时，可能已经扣费的任务转为待核对，已保存 WAV 可继续使用。工作区切换、备份导入和暂停自动创作会停止未完成任务。待核对时可根据任务中的积分阶段和曲目 ID 到谱乐「我的作品」检查。

## 后续与回退

实站验收时核对归档账号的 A/B 歌手、各版目录、配置的 PNG 分辨率和 WAV 路径。已有任务及已保存文件可从运行和下载目录核对。回退本轮目录改动时，撤回谱乐的艺人资料匹配和目录创建变更以及对应测试，再重新构建。
