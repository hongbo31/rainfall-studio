# 直接生成番茄待签合同

本轮根据官网合同预览修正目录上传的第 23–29 步。番茄当前上传表单的「确认签署」请求生成待签合同并打开电子签约页。合同预览正文由官网异步加载。

## 流程

- 新目录批次经「授权签约模式 → 预览合同协议」，正文加载后，程序核对本批作品 ID 与待生成状态，写入本批生成请求，再点击一次官网的「确认签署」。目录流程直接打开预览。遇到额外的番茄畅听同步提示时保留现场并记录截图，供本人核对。
- 从生成请求起最多等待 15 分钟。核对「合同生成中」已结束，同一账号会话中仍有本批发起页，以及它新打开的唯一带有「数据安全验证」的签约页。窗口与作品回执核对通过后才将本批音频、歌词和封面移入回收站。保留版权证明及其它批次正在使用的共享文件。
- 「是否签约」为「否」时，程序回收本批文件后继续处理剩余歌曲。选「是」时，浏览器停在本批电子签约页，由本人完成短信验证和签署。程序读到同一作品的审核或上架回执后自动续跑。
- 保存过生成请求的批次通过原作品 ID 查询合同。15 分钟超时、页面关闭或应用重启后，恢复时使用已有合同入口；官网仍显示待生成时可核对预览。先前进入预览或签约的批次保留原执行状态。

## 文件与验证

- `src/main/fanqie/authorization.ts` 与 `authorize-records.ts` 负责预览及生成请求。`directory-run.ts` 保存生成时间和验证页证据，`directory-signature.ts` 区分数据安全验证与文件签署，`directory-trace.ts` 记录失败及脱敏截图。
- `src/shared/fanqie-downloads.ts` 和 `src/renderer/components/FanqieDownloadUpload.tsx` 共用批次提示，上传确认说明会生成待签合同。番茄目录流程与回执格式在浏览器和 Windows 客户端共用。
- 隔离浏览器通过 24 项目录、筛选及界面回归，番茄基础与授权回归通过 123 项。覆盖正文延迟加载、直接生成、意外同步提示、验证页先于生成结束、缺少验证标记、15 分钟上限和批次续跑。单独复验了重启后仍能识别超时批次并避免重复生成。
- TypeScript 检查、浏览器构建与 Windows Electron 无窗口桥接均通过。桥接检查验证旧批次范围和新批次的待签合同确认文字。真实账号投稿、签署和 Windows 原生窗口待验收。
- 浏览器入口继续使用 `Start-Rainfall-Browser.bat`。回退时恢复本轮源码和测试，保留已记录的作品 ID、合同日志与生产数据。
