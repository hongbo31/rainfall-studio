# 番茄目录分批上传

## 入口与批次

原目录上传逐首进入编辑器，批次过程中看不到卡在哪首歌、哪个步骤。本轮改为在「平台管理 → 番茄音乐 → 执行」选择账号后，统计配置中心下载目录中该账号前缀下的歌曲和可预检数量。每批上限为 1–100，账号管理可保存默认值，执行时可调整。上限 100 且只有 3 首合格歌曲时，该批提交 3 首。

音乐类型、歌曲属性、AI 标注、版权证明和签约模式取自目录匹配的艺人资料。旧资料使用原版、原创、AI 作品和无额外版权证明的原有默认。歌手取自目录。开启签约时，同一批次使用相同签约模式。

## 对应操作步骤

| 原步骤 | 执行与核对 |
| --- | --- |
| 扫描 | 固定所选账号和本次确认的文件清单。记录扫描、已有上传和待预检结果。每一轮核对账号、官方作品目录、署名和本地文件。 |
| 1–2 | 打开番茄创作首页，等待可见的「发布作品」入口后点击。 |
| 3–4 | 在「成品发行」中进入上传表单并添加第一首。校验歌曲卡片索引和可见字段。 |
| 5 | 选择并读回「原创」或「翻唱」。 |
| 6 | 选择并读回「原版歌曲」或「多版本歌曲」。按艺人配置选择纯音乐。 |
| 7 | 打开当前歌曲的音频选择器，等官网显示文件名、格式、大小和上传完成。 |
| 8 | 上传并核对歌词。纯音乐跳过歌词和词作者。 |
| 9 | 输入并核对作品名称。 |
| 10–12 | 依次录入词作者、曲作者及目录歌手，匹配唯一艺人选项，核对详情与选中标签。 |
| 13 | 上传封面，确认裁剪，核对正方形图片预览。 |
| 14 | 根据艺人设置选择 AI 作品的「是」或「否」，并读回选项。 |
| 15 | 需要证明时，在同目录配对同名 PDF，或以「歌曲名_版权证明」命名的 PDF/PNG/JPG。校验当前卡片上的上传回显。 |
| 16 | 只有尚有歌曲时才新增卡片。分批上限与实际可用数量共同决定本批首数。 |
| 17–18 | 核对所有卡片，再点击一次「下一步」。在最终确认前复核账号、查重和文件，随后只点击一次「确认上传」。3 秒后核对是否已进入签约模式页、曲目数和标题。逐首记录官网新增作品 ID。 |
| 19–21 | 选择签约时，按本批签约模式选择独家或非独家，并核对签约身份为「个人」。 |
| 22–23 | 点击「下一步」。当已配置同步到番茄畅听且页面显示「确认同步」时，核对并继续到合同预览。 |
| 24、26–29 | 用户在官网窗口核对合同、点击确认签署并完成两阶段验证码和签署操作。应用记录合同预览与验证窗口的出现。 |
| 25 | 从检测到合同生成或新窗口开始，观察最多 15 分钟。核对生成提示结束、合同预览打开的唯一新窗口以及「数据安全验证」提示。窗口证据和账号、批次、作品 ID 绑定。官网返回相同 ID 和歌名，且状态为审核中或已上架后，把已核对的下载音频、歌词和封面移入回收站。尚未处理的歌曲所需共用材料和版权证明会保留。 |
| 30 | 关闭签约时，每批回执齐全后继续下一批。开启签约时，记录核验窗口后查询官网回执，回执齐全即可继续。若浏览器关闭或应用已重启，可用「核对并继续下一批」。账号配置中途变化时，核对已提交作品并要求重新扫描确认余下歌曲。 |

## 执行证据与恢复

- 「打开执行日志」进入本次运行的目录。番茄账号的状态目录内 `download-runs/<运行 ID>/trace.jsonl` 按时间和序号记录批次、歌曲槽位、步骤、阶段和错误码。失败截图位于 `screenshots/`，对应日志行给出文件名或无法截取的原因。
- 使用页面操作异常、脚本错误和可识别的官网提示作为截图触发条件。截图保留页面结构和可安全保留的报错文案，表单值和敏感内容经过遮盖。第三方验证页面以及已关闭或导航离开的页面只记截图不可用的原因。
- 上传确认前、作品回执尚未读全或浏览器账号发生变化时，保留材料和操作记录。确认状态不明时进入核对流程。只移动所选下载目录中已验证的文件，作品库与版权证明保留。
- 「仅上传」可连续处理多批并将作品留在待授权。文件回收对应已核对的签约结果。应用在重启后可根据操作记录与官网状态核对已有批次。

## 涉及文件

- `src/core/fanqie-downloads.ts` 与 `src/shared/fanqie-downloads.ts` 负责统计、目录与艺人对应关系、版权材料和分批参数。
- `src/main/fanqie/directory-run.ts`、`directory-form.ts` 和 `directory-trace.ts` 负责本地队列、同表单上传、合同续跑、回收和诊断。`upload-broker.ts`、`account-sessions.ts`、`catalog-session.ts`、`authorize-records.ts`、`authorization.ts` 与 `src/main/bootstrap.ts` 连接账号隔离、官网回执、合同和 Windows 本地操作。
- `src/renderer/components/FanqieDownloadUpload.tsx`、`FanqieUploadAuthorization.tsx` 与 `src/shared/contracts.ts` 负责浏览器和 Windows 客户端共用的设置与入口。
- `scripts/Start-Rainfall-Browser.ps1` 按锁文件安装依赖，使用包内的 SQLite 预编译件，并单独运行 Electron 的下载步骤。机器上无需配置 Python 来构建浏览器入口。

## 验证

- 使用独立数据目录、模拟回执和无头页面验证分组、重复回执拦截、跨轮续跑、共用材料和作品库保护、合同边界和错误截图。
- 测试通过 156 项。目录、归档和浏览器桥接 23 项，多歌曲表单 7 项，界面 2 项，路径可移植性 8 项，既有番茄上传和发布基础 95 项，既有无头官网适配和签约 21 项。多首表单与签约测试通过本地夹具拦截平台请求。
- TypeScript 检查、路径可移植性测试、现有浏览器入口的构建和 Windows Electron 本地桥接均通过。Windows 运行件和无头浏览器验证了按所选账号扫描下载目录。
- 浏览器下次从原 `Start-Rainfall-Browser.bat` 启动时加载修复。待验证的范围包括官网真实上传和合同签署、版权证明控件及回执、Windows 原生窗口。正式桌面快捷方式仍指向已验收版本。

如需回退，可恢复本轮源码并保留账号、下载目录、上传回执及执行日志。已进入回收站的文件通过系统回收站恢复。
