# 番茄音乐目录上传与合同续跑

合同预览到签约页的最新流程见[直接生成番茄待签合同](2026-11-21-fanqie-direct-contract.md)。

旧流程把「是否签约」同时用来决定是否创建合同，选「否」会跳过授权签约。上传表单还把当前挂载的歌曲卡片当成全部歌曲，番茄虚拟滚动列表移出屏幕的卡片会被误判为缺失。之前已入库的番茄作品由原批次按作品 ID 核对。

## 流程

| 步骤 | 行为 |
| --- | --- |
| 1–4 | 扫描配置中心下载目录下匹配发布账号前缀的歌手目录。显示总数和可预检数。每批最多取设置的 1–100 首。复用该账号的创作标签页，经「发布作品 → 成品发行 → 发布作品」进入上传表单。 |
| 5–16 | 按歌曲卡片读取艺人发布设置。核对原创或翻唱、原版或多版本、原唱或关联原作品所需控件。逐首等待音频、歌词、封面裁剪和选配版权证明的回执。歌手用目录匹配的艺人，词曲作者用保存的署名。当前卡片核对完成后再添加下一首。 |
| 17–23 | 分别核对当前批次的全部卡片和文件，点击下一步和确认上传，等待 3 秒并断言官网已进入授权签约。按本批作品 ID、合同模式、个人身份和账号的同步平台设置完成合同预览。 |
| 24–25 | 本人核对官网合同并点击「确认签署」。监测合同生成状态最多 15 分钟。校验本批打开的「数据安全验证」，或同一授权流程直接打开的「文件签署」。结合官网同批作品与合同回执，把音频、歌词及封面移入回收站。 |
| 26–30 | 选「是」时，本人完成官网签署和短信验证，程序读取审核或上架回执再自动续跑。选「否」时，合同生成并核对回执后自动执行下一批，作品继续显示官网「待授权」。 |

## 实现

- `src/core/fanqie-downloads.ts` 按账号和歌手扫描并检查材料。翻唱或多版本由 `LocalArtistCreator.tsx`、`src/shared/schemas.ts` 和 `src/core/account-local-artists.ts` 保存原唱或关联原作品 ID。翻唱的本地表单名和官网带 `(Cover …)` 后缀的回执名分别核对。
- `src/main/fanqie/directory-form.ts` 和 `directory-cards.ts` 复用当前表单及滚动容器。按歌曲编号定位当前虚拟行，每首提交前校验材料接收状态。番茄未开放歌曲属性控件的账号使用官网原版默认值。多版本需要账号已开通，并选择官网返回的关联作品。纯音乐仍依照该账号官网表单可用的选项。
- `src/main/fanqie/directory-run.ts`、`authorize-records.ts` 与 `catalog-lookup.ts` 持久化本次签约选择和当前批次的核对证据。官网查重及续跑按标题或精确 ID 查询。旧批次保留创建时的签约选项和恢复逻辑，上传回执用于防止重复投稿。已确认稿件的下载源文件在身份复查后回收，保留版权证明、尚未完成的歌曲共享材料和正式库。签约帮助页不占用签约恢复入口。
- `src/main/fanqie/directory-trace.ts` 保存逐步骤、批次及歌曲序号。页面错误附 PNG，签约页图片按实际错误位置生成脱敏视图，手机号、验证码和协议正文留在官网。页面已关闭或错误发生时尚未打开时，日志记录无法截图的原因。执行窗口可打开对应日志目录。
- `FanqieDownloadUpload.tsx` 与 `FanqieUploadAuthorization.tsx` 区分「签署后继续」与「合同生成后继续」。使用现有账号授权、发布权确认和独立浏览器会话。合同签署和验证码由本人在官网操作。

- 浏览器继续使用仓库中的 `Start-Rainfall-Browser.bat`。Windows 客户端和浏览器共用调用接口、批次记录和目录上传逻辑。
- 回退时仅恢复本轮源码、交接和测试。若新版已产生投稿，保留批次日志、官方回执和工作库。官网已有的「待授权」或「审核中」作品按原 ID 接续。
