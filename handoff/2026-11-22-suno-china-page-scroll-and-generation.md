# 苏诺之音页面滚动与生成结果核对

## 发现

- 在苏诺之音官网的匿名会话复现截图中的错位。以 2041 × 1277 窗口试点「自定义模式」时，Chromium 将外层工作区横向滚动了 346 像素、纵向滚动了 126 像素。表单和歌曲列表一起移到固定顶栏下方。
- 浏览器工作台北京时间 03:27 的旧记录停在 `generation`，登记一次提交尝试，未记录两首结果或已保存文件。日志只记录了 `PULE_BROWSER_INTERRUPTED`，该次任务的准确中断点待核对。
- 用无头网页替身复现了两种能产生相同通用错误的情况。第一种是歌曲列表短暂渲染出行但没有歌名。第二种是表单检查通过后，「创作」按钮在实际点击前失去可操作性。另复现了旧代码漏识别官网的「正在生成…」文案。

## 改动

- `src/main/suno-cn-browser-page.ts` 在本次任务页限制外层容器的滚动，保留表单及作品列表的内部滚动。生成前确认列表和按钮可用，识别官网排队和生成状态。生成后从同一次列表读取中确认顶部两条新结果及对应菜单，再进入 B 版改名和两首 WAV 下载。遇到空白歌曲行会继续等待。创作提交仍只尝试一次。
- `src/renderer/components/PuleBrowserGeneration.tsx` 为列表未就绪、提交未确认和歌词确认失败显示对应提示。历史通用中断按记录阶段提示核对创作或 WAV 下载。
- `tests/suno-cn-browser.test.mjs` 和 `tests/fixtures/suno-cn-browser.html` 覆盖外层滚动、临时空歌名、已有任务进行中、提交按钮失去可操作性。保留两版歌名、WAV、封面及歌词归档断言。

## 验证与交付

- 官网 2041 × 1277 和 1366 × 768 两个窗口尺寸的无头检查通过。选择自定义模式、填写、展开高级设置及试点创作按钮后，外层位置保持在原位。较小窗口的内部表单仍正常滚动。未调用官网创作。
- 26 项苏诺之音与归档回归通过。TypeScript、同一浏览器 BAT 的隔离构建、实编 Electron 浏览器服务的无头启动检查通过。Windows 客户端共用此执行逻辑及记录界面。真实账号的生成、改名、WAV 下载、实际封面 API 和 Windows 原生窗口待验收。
- 新启动的 `Start-Rainfall-Browser.bat` 会构建本次修改。当前浏览器进程按其启动时的源码快照继续运行。03:27 的历史任务可先在官网「我的创作」核对。
