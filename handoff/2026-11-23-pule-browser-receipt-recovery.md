旧执行器在进入可能扣费的提交边界后，把网页异常统一记为这条提示。历史数据缺少当时的网页错误和提交前的歌曲列表，因此能定位到回执环节，无法核实谱乐实际是否接到请求。原有自动核对只处理 API 任务，网页任务保持待处理，第三个独立计划「番茄音乐平台上传」一直排队。

## 改动

- `src/main/pule-browser-page.ts` 在榜首核实后保存提交前的歌曲 ID。新版计划可凭新增 ID 匹配同名歌曲，避免已存在的同名榜首让已生成的 A、B 被误判。网页核对只接受相对旧榜首新增的相邻两首、且匹配唯一的歌曲，沿用原列表的 A、B 顺序。
- `src/main/plan-pule.ts`、`src/main/bootstrap.ts`、`src/main/browser-accounts.ts`、`src/main/task-music-windows.ts` 用本次谱乐账号的专属会话开启无头页面核对。核对成功后从原歌曲 ID 继续下载。提交失败后记录清洗后的网页错误码，执行详情可查看。
- `src/core/plan-pule.ts`、`src/core/plan-center/storage.ts`、`src/shared/plan-pule.ts` 持久化提交前记录并限制自动核对最多四次。重启后已有的提交证据可继续核对。多组匹配、登录状态异常、列表不可读取、未找到匹配和历史缺少记录分别显示相应原因。
- `src/core/publication-task-integration.ts` 在核对用尽或历史缺少提交前记录时，让父任务记录这个计划的失败并进入后续独立计划。原提交保留待核对状态和证据。 `src/renderer/plan-execution-labels.ts` 与 `src/renderer/pages/PlanCenter.tsx` 展示核对进度和网页诊断。
