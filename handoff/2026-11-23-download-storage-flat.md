# 下载歌曲平铺存放与防重

更新日期：2026-11-23（北京时间）  
任务：RF-012

> 历史记录：本任务的“未来下载平铺在根目录”约定已被用户后续要求及 RF-015 取代。RF-012 的哈希复用、防止同名异内容覆盖、保留旧文件规则仍有效。后续默认按账号/A-B 歌手/提示词引擎建目录，见[RF-015 下载目录交接](2026-11-23-download-artist-prompt-directories.md)。

## 用户目标

截图中第二种方式是期望结果：WAV、JPG、TXT 等歌曲文件直接存放在当前配置的下载根目录；不要额外创建账号、艺人、提示词或单曲碰撞目录；相同文件不要在本地重复落盘。后续下载生效，既有真实素材和目录不自动移动或删除。

## 原因与实现

- `src/main/pule-browser.ts` 新任务直接写配置下载根目录，不按账号、艺人或提示词建目录。WAV 与歌词/封面附件使用相同文件名主体；相同内容哈希复用，标题冲突时用稳定的远端歌曲 ID 哈希后缀区分。
- `src/core/download-filenames.ts` 停止创建单曲名碰撞目录。
- `src/core/download-archive.ts` 作品库、计划和发布归档写入下载根目录；同名同内容校验哈希后复用，不同内容在平铺目录中使用稳定哈希后缀。通用单文件下载也采用相同内容复用和异内容后缀规则。
- 旧目录仍可读取；已有文件不移动/删除。归档指纹未变化且旧文件仍存在时，直接复用旧路径，不再从旧子目录复制一份到根目录。作品内容变化时，哈希完全相同的附件复用既有路径；只有新增内容写入根目录，因此历史作品变更后的附件可能暂时与旧素材分处新旧位置。
- 项目长期偏好同步写入 `handoff/PROJECT-HANDOFF.md`，台账登记为 RF-012。

## 影响与验证

- 新歌曲及其 WAV/JPG/TXT 文件直接平铺在用户配置的下载根目录，不会新建歌名 `(2)` 目录或账号/艺人/提示词目录。
- 相同字节内容不会再写出第二份本地文件；同名不同内容用哈希后缀分开，避免覆盖。未变化的旧归档继续引用原路径，避免为平铺而重复复制旧歌曲。
- 不清理截图中已存在的目录或歌曲文件。
- `git diff --check` 通过。按本轮要求，没有新增或运行测试，也没有触发真实下载；实际根目录和 Windows 原生客户端仍待验收。
- 相同歌曲的新任务仍可能再次从平台传输 WAV；本次保证本地相同内容复用，不保证平台侧传输请求跳过。

## 后续与回退

- 验收时在隔离根目录下载一首新歌曲，确认 WAV/JPG/TXT 都位于根目录；重复归档后没有副本；同名异内容结果使用不同哈希后缀；读取旧目录仍可重试封面。
- 回退时恢复 `src/main/pule-browser.ts`、`src/core/download-archive.ts`、`src/core/download-filenames.ts` 的 RF-012 改动，并同步更新本交接、`handoff/PROJECT-HANDOFF.md` 与项目台账。不要删除已经存在的音乐目录。
