# 番茄目录上传的歌曲字段校验和单曲修复

## 原因

番茄的上传组件可以先显示「上传完成」，「下一步」还会校验歌曲文件是否有可用的上传凭据，并校验其余歌单字段。用户提供的页面 HTML 包含带歌曲序号的表单控件、字段级错误和卡片删除图标。旧脚本点击「下一步」后直接等待「确认上传」弹窗，出现红字时只会等到超时。

## 改动

- `src/main/fanqie/directory-form.ts` 在逐首填写、点击「下一步」前和打开上传确认框后核验完整歌曲、歌词、作品名称、词作者、曲作者、歌手和封面。点击「下一步」后按官网表单控件识别红字，并重新校验处理过的歌曲。
- 完整歌曲缺失或报错时，点击对应草稿卡片标题旁的删除按钮并核对删除弹窗，再用本批原素材重建该卡片。只有一首时，先增加一张空卡片，满足番茄至少保留一首的要求。卡片编号变化后仍以原批次序号关联素材、日志和回执。
- 歌词、标题、作者、歌手或封面缺失时，优先补填对应字段。官网报错的控件已存在上传记录、作者标签或封面时，重建该草稿以恢复正常编辑。纯音乐继续按原有规则校验。
- 每首最多自动修复两次，未识别的表单错误和持续错误有独立提示。最终确认上传后已换到回执核对阶段，页面报错时记录状态和截图。
- `src/main/fanqie/directory-cards.ts` 和 `src/main/fanqie/directory-validation.ts` 将读写限定在本次打开的表单，并读取错误字段。`src/main/fanqie/directory-trace.ts` 使用真实表单的错误样式定位截图，允许显示固定报错文案。`src/shared/fanqie-downloads.ts` 增加对应用户提示。
- `tests/fanqie-directory-form.test.mjs` 和 `tests/fixtures/fanqie-directory-site.mjs` 覆盖媒体校验失败、缺失字段、草稿重新编号、持续报错和最终确认后的页面错误。

## 验证和回退

- 浏览器预览构建、TypeScript 检查和 52 项相关测试通过。构建与隔离测试的源码哈希一致。
- 40 首合成歌曲的专项测试覆盖第 2 首音频显示「上传完成」后仍被官网表单判为异常的情况。测试核对仅该曲重传，授权列表仍有 40 首，最终确认仅执行一次。原地补齐六个字段的专项测试核对了六份脱敏 PNG 和原批次歌曲序号。
- 浏览器与 Windows 客户端共用目录上传逻辑。Windows 隔离 Electron 测试核对了重试达到上限时的提示和执行入口。真实番茄账号提交及 Windows 原生窗口仍待验收。
- 回退时恢复以上文件并重新构建。浏览器沿用 `Start-Rainfall-Browser.bat`。
