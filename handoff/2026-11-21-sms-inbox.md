# 远控与安卓业务通知

2026-11-21

Rainfall Studio 在「账号管理」上方提供「远控」。Windows 客户端和浏览器版共用页面、接收服务和本地数据。可按手机查看在线状态、短信到达记录和作品审核通知。

## 使用

1. 在电脑打开 Rainfall Studio，进入「远控」，选择手机可访问的网卡并点击「启动接收」。手机和电脑可使用同一个 Wi-Fi，也可使用已有的可互访的私有网络。
2. 手机相机扫描页面「下载安卓 App」里的二维码，下载并安装 `Rainfall-SMS.apk`。把电脑端的接收地址粘贴到 App，填写手机名称。两端输入相同的 6 位数字口令，先在电脑点「开始配对」，再在手机点「配对」。每个口令有效期为 5 分钟，配对成功后用新口令添加下一台手机。
3. 已配对的手机点「开启自动上报」，按 Android 的提示授权。手机显示同步状态通知，可随时停止同步或解绑。电脑端在 Rainfall 运行且接收服务已启动时接收记录。系统交付给 App 的每条新短信会进入「短信到达记录」，显示接收时间和来源手机。
4. 可用另一台测试手机发一条普通短信，检查「短信到达记录」是否新增一行。要另外核对作品审核识别，可用样例 `【番茄音乐】您的作品《雨夜》审核通过。`。

配对口令框显示已输入的位数。口令不足 6 位时，点「开始配对」会提示并将焦点移回输入框。电脑端会将全角数字转换为普通数字，手机端输入同一组 6 位数字。

重新打开 Rainfall 后，可在相同网卡上重新启动接收。电脑 IP 变化后，选择当前网卡启动接收，再用新地址和口令为手机配对。配对中途掉线时，可在电脑移除未连接的记录并重新开一个口令。

## 改动与影响

- 按用户要求将模块显示名称改为「远控」。`src/renderer/main.tsx` 提供侧栏和面包屑名称，`src/renderer/pages/SmsInbox.tsx` 用于页面标题和操作提示，`src/main/bootstrap.ts` 同步更新接收错误提示。模块继续通过 `sms-inbox` 入口及既有存储读取手机配对和历史记录。
- `src/renderer/pages/SmsInbox.tsx`、`src/renderer/sms-inbox.css`、`src/renderer/main.tsx` 提供页面、设备筛选、配对和状态刷新。`src/shared/sms-inbox.ts`、`src/shared/bridge.ts`、`src/shared/contracts.ts` 共用数据格式和调用接口。
- 配对表单原先在输入不足 6 位时置灰按钮，输入时占位提示也会消失。共用页面改为显示位数并在点击时校验。只有符合 6 位数字要求的口令才提交给接收服务。
- `src/main/sms-inbox.ts` 和 `src/main/bootstrap.ts` 提供独立 HTTPS 接收服务、限次配对、每台设备独立凭据和撤销。证书私钥由 Windows 本机凭据加密功能保护。设备和最近 500 条业务通知放在所选数据根下的 `runtime/sms-inbox`。作品 SQLite 库无需迁移。
- `src/main/sms-apk.ts` 在选定网卡提供单独的 APK 下载地址。服务只响应安装包下载，跟随「启动接收」和「停止接收」。共用页面用 `qrcode-generator` 在本地绘制二维码。下载地址只含网卡地址、端口和文件名。
- Android 的到达上报仅提交事件 ID 和接收时间。`src/main/sms-inbox.ts` 根据配对凭据关联来源手机，按设备和事件 ID 去重。桌面在数据根的 `runtime/sms-inbox/arrivals.json` 保留最近 500 条到达记录，配对状态和审核通知继续使用原文件。短信原文和发件号码不进入到达上报。
- Android v1.0.1 移除了 `MainActivity.java` 的发件人表单和 `SmsSyncService.java` 的固定号码筛选。平台换号码后，匹配审核模板的新通知仍逐条同步。传输字段为平台、作品名、审核状态和时间。验证类消息、链接和其他未匹配内容在手机端丢弃。电脑暂不可达时，手机队列最多保留 64 条待上报的审核通知。
- Android v1.0.2 让 `SmsSyncService.java` 在开启监听期间为每次系统交付生成到达记录，通过 `InboxClient.java` 上报。`PendingArrivals.java` 与 `PairingStore.java` 保存最多 500 条待传记录。重试使用同一个事件 ID，连接恢复后分批连续补传。安装旧版电脑端时，App 提示更新 Rainfall，原有审核通知仍可同步。
- Android v1.0.3 从 `MainActivity.java` 移除「支持的短信格式」入口，避免将审核示例误认为到达条件。`SmsSyncService.java` 对系统交付的新短信先记录到达事件，再单独识别审核通知。`AndroidManifest.xml` 版本号升级为 4，可用同一签名覆盖升级。
- `package.json`、`package-lock.json` 增加生成 HTTPS 证书的依赖。`scripts/Start-Rainfall-Browser.ps1` 使用锁文件中的 Windows 预编译组件，并单独安装锁定版本的 Electron，避免准备浏览器时重新编译 SQLite。

## 验证范围

- 「远控」改名通过 8 项回归、TypeScript 检查和 Windows 构建。浏览器无头用例验证侧栏、顶部路径和页面标题，以及接收与配对入口。Windows 原生窗口待验收。
- TypeScript 检查和 10 项短信接收、共用页面、浏览器桥接、平台管理及基础回归通过。`Start-Rainfall-Browser.bat -BuildOnly` 从隔离目录构建 Main、预加载、Core 和渲染层。无头 Chromium 通过实际 Electron 浏览器工作台的隔离库打开新页面并读取状态。
- 安卓 v1.0.1 通过模板识别、私人短信及验证码排除和配对地址测试。隔离联调覆盖证书指纹、配对、心跳、两条同内容通知分别入库、网络重试去重及解绑。APK 校验了 v2/v3 签名、资源对齐和 SHA-256，签名证书与 v1.0.0 一致。浏览器启动构建已复制此版 APK。真机覆盖安装和实际短信投递待验收。
- 逐条到达记录通过 TypeScript 检查、隔离启动和 11 项回归。无头页面验证两条同时间记录分别显示和按手机筛选。接收服务验证严格字段、配对鉴权、重启恢复和重试去重，Java 客户端与实际接收服务通过隔离联调。v1.0.2 已校验签名与 v1.0.1 一致，浏览器启动构建已核对随包 APK 哈希。真机投递和 Windows 原生窗口待验收。
- v1.0.3 已检查 APK 中的界面提示、同签名升级、短信到达和审核通知隔离联调。浏览器启动构建包含哈希一致的新版 APK。真机覆盖安装和实际投递待验收。
- 扫码下载改动通过 TypeScript 检查和 10 项基础及短信回归。无头测试解码实际渲染的二维码并下载 APK，下载文件、浏览器随包文件和 Windows 隔离候选中的 APK 与签名原包哈希一致。停止接收后旧链接关闭，哈希不符时接收功能仍可使用，页面提示安装包暂不可用。手机相机实扫和 Windows 原生窗口未验收。
- 配对表单修复通过 TypeScript 检查、原 BAT 隔离构建及 10 项回归。`tests/sms-inbox-ui.test.mjs` 覆盖输入 4 位后的反馈和焦点、全角数字转换及补足 6 位后的配对提交。Windows 原生窗口和真机配对未在本轮验收。
- 全量 Core 集成测试在隔离目录运行，229 项通过，5 项失败。失败涉及 100 首样本素材目录缺失、两项腾讯发布协议断言、每日计划迁移和诊断音频候选状态。详细失败项见构建目录的 `sms-inbox-qa-d8b37c3d/repo-integration.log`。
- Windows 原生窗口、真实手机权限和平台实际下发的短信格式待验收。离线样例用于验证识别规则，需要按脱敏的真实通知补充不同格式。Android 机型能否授权新短信接收依系统和安装来源而定。

## 构建与回退

- 回退改名时，撤回客户端显示名称、相关提示和 `tests/sms-inbox-ui.test.mjs` 中的名称断言，再重新构建。已有配对与接收记录可继续读用。
- 浏览器从仓库根目录的 `Start-Rainfall-Browser.bat` 构建和启动。退出已运行的预览后重开，扫码即可下载 v1.0.3。覆盖安装后，在手机重新开启自动上报。Android 用 `android/sms-inbox/Build-Android.ps1` 构建和签名，当前产物 `Rainfall-SMS.apk` 的 SHA-256 为 `c95496c9c8be9a253aa6d3763d3748a64a8d7988ee5d3445981fd43f6a978da1`。保留构建目录下的 `signing` 目录，后续 APK 更新需要同一签名。如需恢复格式示例，可恢复页面入口并用同一签名和更高版本号覆盖安装。回退到达记录功能时可保留电脑端的 `arrivals.json`。
- `scripts/build-desktop.mjs` 校验构建目录 `android-sms` 下的 APK 和校验文件后，将两者加入运行快照。`Start-Rainfall-Browser.ps1` 从原检出定位构建目录，`Build-Latest.ps1` 从本次构建根定位，`scripts/package-tme-candidate.mjs` 将文件带入 Windows 包。需要时可以用 `RAINFALL_SMS_APK_DIR` 指定现有 APK 所在目录。要回退扫码功能，可撤回下载服务、页面和随包复制改动后重建，并用构建目录下的签名 APK 安装。
- 回退配对表单提示时，撤回共用页面、样式及 `tests/sms-inbox-ui.test.mjs` 的本轮变更后重建。配对协议和已配对设备状态可继续使用。
- 回退时先停止手机同步，再撤回本轮短信接收源码、依赖和浏览器启动脚本修改后重建。`runtime/sms-inbox` 中的本地接收记录可保留。桌面快捷方式和当前正式库按原桌面交付策略处理。
