# 下载按账号、歌手与提示词归档

更新日期：2026-11-23（北京时间）  
任务：RF-015

## 用户目标

把配置中心的下载目录作为根目录。未来属于歌曲/版本的 WAV、封面、歌词和相关附件，分别放入 `<账号名称>_<A或B版歌手>_<提示词引擎名称>` 目录，例如 `素素_锤锤虎_6080台湾苦情女歌手`、`素素_锤锤狐_6080台湾苦情女歌手`。目录名组件清理 Windows 禁止字符。现有文件夹与文件不迁移、不删除。

本要求覆盖 RF-012 的“下载根目录平铺”约定；RF-012 对内容哈希复用、异内容不覆盖和旧文件保留的规则继续有效。

## 实施内容

- `src/core/download-archive.ts` 从账号本地艺人资料、A/B 歌手和提示词模板名称产生版本目录；计划快照流程使用其冻结的账号名、A/B 歌手与模板名称。A/B 歌手名相同时给 B 目录添加 `_B` 以避免两个版本共用目录。
- Core 的计划归档按每个版本进入对应目录，WAV、封面、歌词及证书、授权附件、视频等支持文件保持作品名和现有附件子目录规则。旧的无版本归档在后续归档时生成新路径；哈希一致的旧文件继续引用原位置，不复制迁移。
- `src/main/pule-browser.ts` 直接下载流程按 `PuleScope.archiveFolderNames[version]` 写入 A/B 目录，歌词和生成封面跟随该版本 WAV；重试/补封面继续通过已记录 WAV 路径定位原目录。
- `src/core/download-artifact.ts` 有明确作品归属的原音频、证书、封面、封面任务和封面请求导出使用作品对应目录。独立歌词结果尝试以歌词任务的音乐人名、提示词名及唯一匹配的默认账号艺人资料推导目录。
- 番茄批量发布流程读取既有账号/歌手/提示词目录，不负责把文件下载到本地；该读取方式无需更改。作品发布账号与作品艺人归属不一致时，以执行记录提供的发布账号名和所选艺人版本生成目录，需在正式场景验收。
- `src/shared/download-archive.ts` 无需扩展：已有 `DownloadArchiveFolder.name` 与 `audioVersion` 可以记录目录名和版本；Pule scope 已携带 A/B 目录名。

## 无法从现有模型可靠推导的入口

- `materials` ZIP 是批次级导出，可包含多首歌曲/多个艺人，没有唯一 A/B 歌手和提示词所有者，继续放在配置根目录。
- 独立歌词结果在无唯一账号/艺人匹配（例如多个账号共享相同音乐人和提示词，且未配置默认下载账号）时，保留配置根目录位置。
- 任何作品缺少艺人或账号元数据时，相关通用导出也继续使用配置根目录；不猜测账号或艺人。

## 影响与边界

- 只改变本轮之后的目标下载位置；没有搬移旧目录、旧作品或素材。
- 每个确定的 A/B 版本使用独立物理目录。相同字节仍按既有哈希逻辑复用；异内容不会覆盖同名资产。
- 目录组件会清理 Windows 不允许的字符并限制长度；若账号或歌手名称含非法字符、超过长度限制，实际目录名会经过安全归一化。A/B 歌手相同时，B 目录追加 `_B` 避免两个版本落入同一目录。
- 浏览器端与 Windows 客户端共用 Core 下载归档逻辑；直接浏览器自动化下载从 Core scope 接收 A/B 名称。
- 没有修改 `handoff/PROJECT-HANDOFF.md` 或 `docs/project/board.md`，由 xb 汇总。
