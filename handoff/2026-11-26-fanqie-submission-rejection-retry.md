# 2026-11-26 番茄作品拒绝后自动剔除与复核

## 需求

用户要求：点“下一步”并确认上传后，若 4 秒内顶部出现“作品信息提交失败：《歌名》……”，按本批原始歌曲顺序定位对应歌曲，删除官网表单卡片，重新提交其余歌曲复核，最多重复 7 次；官网未接收的拒绝歌曲也要从本地下载目录移除。

此前用户明确确认本地回收范围为歌曲作品条目及其音频、歌词、封面。失败任务记录保留，作为歌名、原始序号和处理结果的本地审计记录；版权证明不回收。

## 实施

- `src/main/fanqie/directory-form.ts`：确认上传按钮点击后观察 4 秒，匹配用户截图中的 `//span[contains(text(),"作品信息提交失败")]`，解析《歌名》并唯一匹配表单条目。日志沿用本批原始歌曲序号，即使前面的拒绝卡片已删除也不改变编号。删除前核对当前官网卡片标题序号、作品名、音频回执和唯一删除弹窗；每次移除后重新点击“下一步”并确认。首次提交后最多再重试 7 次；若第 8 次确认仍被拒绝则停止并保留该歌曲供人工核对。
- `src/main/fanqie/directory-run.ts`：移除卡片前通过本批目录查询检查该歌曲没有新官网作品回执；查到回执、账号变化或读取不完整时停止。官网卡片删除后，重新扫描确认下载根和材料身份未变化，再保护作品库、同批及其他歌曲共享文件和版权证明，仅将拒绝歌曲的音频、歌词、封面移入系统回收站；把任务 JSON 归档，批次失败条目仍记录原歌序与拒绝状态。重试预检和确认写入只作用于仍活跃的歌曲，不会重建已归档的拒绝任务。剩余歌曲独立读回执及继续合同流程。
- `src/main/fanqie/directory-trace.ts`：记录拒绝观察预算、提示数量、歌名匹配数、重试上限、新回执数量和本地回收材料数，不写本地路径。
- `src/main/fanqie/catalog-session.ts`、`src/shared/fanqie-downloads.ts`：增加歧义、次数耗尽、全批拒绝及本地回收失败的状态提示。
- `handoff/PROJECT-HANDOFF.md`：记录当前状态并关联本说明；更新前次回退记录的状态说明。

## 安全边界

- 歌名缺失/歧义、发现该歌出现新官网记录、作品卡片身份不符、目录或文件身份发生变化、共享引用、删除确认无法核实、回收站回调不可用或回收失败，都会暂停，不猜测目标。
- 被拒绝歌曲的本地音频、歌词和封面移入系统回收站，可从回收站恢复。版权证明及其他歌曲素材保留。
- 如果只剩一首，番茄表单至少要求一个歌曲卡片，因此保留该拒绝卡片供核对、回收对应本地素材并停止，不提交空表单。若超过 7 次重试上限且仍有多首待复核歌曲，则保留终止拒绝卡片及其本地素材供人工处理。
- 这只适配批量下载目录上传表单。单首上传路线不涉及用户本轮请求的本地下载批次，不受此改动影响。
- 浏览器端与 Windows 客户端共用 Main 中的表单及批次逻辑；本轮只做源码静态审阅，未进行 Windows 原生运行验收。
- 合同接受仍是用户确认边界；本功能不会自动接受或签署协议。

## 验证与未验证

- 已对表单循环、原始索引映射、批次活跃歌曲集合、本地回收边界和错误路径做静态代码审阅；未运行测试、构建或官网操作。
- 未验证官网提示真实消失时序、实际表单删除弹窗、登录态下作品目录检索结果，以及 Windows 系统回收站回调。`%LOCALAPPDATA%\RainfallStudioLauncher\verified-desktop.json` 当前不可用，因此未确定生产运行包/数据根、未启动可见客户端、未更新桌面入口。

## 回退

还原 `directory-form.ts` 确认上传后的原流程，移除 `directory-run.ts` 的拒绝回执校验和拒绝素材回收，恢复 `directory-trace.ts` 的细节白名单，并移除 `catalog-session.ts`、`shared/fanqie-downloads.ts` 的新提示及本交接记录。不要自动恢复已经进入系统回收站的素材；如需恢复，由用户从回收站操作。
