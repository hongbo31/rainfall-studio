# 发布任务仅关联计划中心的真实计划

日期：2026-11-20

后续发布设置见 [发布任务沿用关联计划的发布节点](2026-11-20-publication-by-linked-plan.md)。

## 原因与修复

关联窗口原来只检查记录是否输出音乐。创作中心的歌曲任务和更早的单次创作也复用了同一套计划存储，因此歌曲名和「单次创作」误入候选。部分已完成的一次性计划还会直接复用旧运行，跳过计划的实际步骤。

- 计划中心主列表与发布任务的关联窗口共用计划定义判定，排除创作中心的歌曲任务和旧单次创作。发布侧再筛选具备音乐输出的计划。已有歌曲、创作任务和历史记录不做迁移或删除。
- 保存、开始和续跑都检查关联计划资格。旧发布任务有关联失效时，界面提示编辑并重新关联。已经登记的上传仍可查看和核对。
- 执行采用任务保存的计划顺序。没有可复用的同版本进行中执行时，实际启动计划中心的新运行，包括一次性计划的手动启动。按计划自身已配置的步骤推进，当前计划完成后才开始下一项。全部完成后使用发布任务选定的平台上传，既有条款确认和收件去重仍生效。

## 涉及文件

- 计划定义与入口：`src/shared/plan-center.ts`、`src/core/plan-center/index.ts`、`src/renderer/pages/PlanCenter.tsx`。
- 发布任务选择与执行：`src/core/publication-task-integration.ts`、`src/core/publication-tasks.ts`、`src/renderer/components/PublicationPlanPicker.tsx`、`src/renderer/pages/PublishCenter.tsx`。
- 复现与回归：`tests/publication-tasks.test.mjs`。

## 验证及回退

- TypeScript 检查、共用 React、Electron Main、Core、预加载的后台构建，以及 40 项发布与计划相关测试通过。
- 使用实际构建的浏览器界面与隔离 SQLite，核对计划中心和关联窗口都只显示真正的计划，旧歌曲关联无法立即执行。按与列表相反的顺序勾选后，验证只有第一个计划先启动实际流程，完成后才启动第二个。
- 未打开 Windows 原生窗口、未进行真实生成、上传或签约，也未切换桌面快捷方式。浏览器使用原有 `Start-Rainfall-Browser.bat` 重新打开即可。
- 回退只撤回上列文件的本轮改动并使用上一已验证运行包。现有库无需重建。旧版会重新显示不合格的关联候选，使用时应核对既有任务。
