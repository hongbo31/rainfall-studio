# 发布任务的关联计划失败隔离

2026-11-20

## 执行行为

发布中心从任务启动时保存的顺序逐个执行关联计划。某项计划启动报错、执行失败、单独停止，或其执行记录缺失时，把计划序号、名称和原因写入本次任务记录，然后推进下一项。计划中心显示为「待处理」的明确步骤错误和发布准备错误也会按单项记录。仍在运行、等待资料、等待平台确认或核对原回执的计划沿用各自的等待流程。点击发布任务的「停止」会结束该任务的后续步骤。

全部关联计划处理完以后，发布中心显示「已完成」「部分失败」或「失败」。部分失败和全部失败的记录按本次任务统计成功与失败数量。在「记录」可以查到报错的计划和原因。

## 实现与影响

- `src/core/publication-tasks.ts` 将启动计划和记录关联写入同一事务，启动异常时记录该项失败。推进时读取已持久化的失败计划 ID 和关联运行 ID，避免重复处理这两类计划。启动后有尚未执行的计划被删除或改版时，到该项才校验并记录。
- `src/core/publication-task-integration.ts` 读取计划中心的步骤状态和发布准备记录，识别明确错误。原计划和投稿回执仍可在计划中心核对。旧发布任务已有的投稿回执继续走原来的核对流程。
- `src/shared/publication-tasks.ts` 为运行记录增加可选的 `planFailures` 和终态 `partial`。`src/renderer/pages/PublishCenter.tsx`、`src/renderer/publication-tasks.css` 显示「部分失败」、数量与记录，并支持按状态筛选。

## 验证与回退

- `tests/publication-tasks.test.mjs` 复现四个计划在第二项出错后结束整批的旧行为。修复覆盖续跑、同名计划、定时启动异常的事务回滚、执行期间删除计划、全部失败与显式停止。
- `tests/plan-workflow-refactor.test.mjs` 覆盖发布准备异常和继续等待既有平台回执。`tests/platform-management-ui.test.mjs` 验证列表、部分失败筛选和记录中的计划名称与原因。
- 浏览器端通过 Playwright 无头验证发布中心的任务列表、状态筛选与执行记录。Windows 端同一套任务逻辑、主进程、预加载和渲染构建通过类型检查及隔离构建。扩展回归共 62 项通过，另有一项旧工作台用例因找不到旧的「选择歌曲」控件而超时，修复前的隔离副本也复现了同一失败。
- 真实平台投稿及 Windows 原生窗口待验收。回退时撤销本轮关联计划执行、结果显示与对应测试，按桌面交付策略使用已验收包。切换前在隔离环境核对任务和记录。
