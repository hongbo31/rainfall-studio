# 手机远控与画面共享

## 使用方式

- 电脑「远控」页的「接收与配对」可选择网卡并启动接收，启动后显示 APK 二维码和配对表单。用同一局域网的安卓手机扫码安装 1.1.0。
- 首次配对时，把电脑复制出的完整接收地址（含 `#` 后的内容）发给手机，粘贴到「电脑端配对地址」。电脑填自定的 6 位数字并点击「开始配对」。手机填写名称和同一个口令并点击「配对」。接收地址未变时，已配对的手机可以直接连接。
- 在手机 App 打开「远控」。电脑选择这台手机和会话方式，点击「请求连接」，再在手机点击「允许本次会话」。
- 电脑显示「等待手机连接」时，当前选中的配对记录还没有来取请求。保持手机处于 App 的「远控」页面，核对接收地址和网络。电脑显示「等待手机确认」时，手机端已经来取请求，可在手机上确认。旧设备与新设备同名时，按配对时间区分，优先选「远控页已连接」的记录。
- 跨网络时，可让 Windows 和 Android 加入同一个 Tailscale 私有组网。在电脑停止旧接收，在「接收网卡」选择 Tailscale 的 `100.64.0.0/10` IPv4 网卡并重新启动，手机使用新接收地址重新配对。仍从 Rainfall 的「远控」发起会话和在手机确认。
- 「操作 Rainfall 手机端」共享手机 App 的连接诊断页。电脑支持点击、拖动滑动、鼠标滚轮及返回。画面获得焦点时可用方向键滚动及退格键返回。手机离开该诊断页、失去窗口焦点或锁屏时结束控制。
- 「查看手机所选应用」需要 Android 14 或更新版本。手机在系统窗口选择「单个应用」并确认共享，可由手机打开要查看的短信会话。外部应用画面仅查看。系统授权界面的选项由 Android 提供，系统在部分设备上也会提供整个屏幕选项。停止共享可用前台通知、系统共享控件或手机远控页。
- 连接请求有效期 90 秒，已确认的会话最多 5 分钟。电脑在 Rainfall 工作台内切换到其他模块时保留本次会话，也可通过小窗查看画面和断开。隐藏或关闭整个工作台、关闭接收、解除配对、任一端失去连接或任一端执行断开会结束会话。
- APK 1.2.0 给每次 App 安装分配一个随机标识。同一安装重新配对时替换旧连接凭据并保留设备 ID。同名的不同设备分别保留。旧版配对通过手机远控页的已认证连接登记标识，未登记的历史记录仍可在「短信接收」逐条确认后解除配对。

## 代码与数据

- `src/renderer/main.tsx`、`src/renderer/pages/RemoteAssist.tsx`、`src/renderer/remote-assist.css` 提供共用页面。`src/renderer/pages/SmsInbox.tsx` 保留短信接收、到达记录、业务通知和下载二维码。
- 旧页面在接收未启动或尚未配对时会禁用连接，启动和配对原先要到「短信接收」完成。远控页现在嵌入同一接收设置，显示当前缺少的步骤，并在「手机画面」下提供可展开的操作顺序。两个页面使用同一个局域网接收服务和 APK 校验流程。
- `src/shared/remote-assist.ts` 约束会话和操作。`src/shared/bridge.ts`、`src/shared/contracts.ts` 和 `src/main/bootstrap.ts` 共用 Windows 主进程和浏览器工作台的受信入口。`src/main/remote-assist.ts` 管理内存会话、手机确认、画面有效期和一次性输入，`src/main/sms-inbox.ts` 复用已配对设备和局域网 HTTPS 接收器。
- `android/sms-inbox/` 新增独立的远控页面、传输和系统共享服务。系统共享附带停止通知，锁屏和所选画面失去可见性会停发。手机触控只派发到 Rainfall 自己的诊断视图。短信处理和保存规则沿用原有流程。
- 手机会话和画面保留在内存，接收端和前端在会话停止或画面过期后释放。现有作品库、配对文件和短信记录不需要迁移。配对地址使用局域网或私有组网 IPv4 及证书指纹。
- 本机存在两条同名的手机配对，旧远控页默认选最早记录，也会在任何待确认会话显示同一提示。`src/main/remote-assist.ts` 现根据通过配对鉴权的远控轮询单独跟踪手机接触时间，`src/main/sms-inbox.ts` 和 `src/shared/remote-assist.ts` 将该状态和配对时间交给共用渲染页。选择排序和诊断无需迁移或删除配对。
- `src/main/sms-inbox.ts` 在有效的六位配对码和手机安装标识匹配时更新该设备的凭据，取消旧凭据和已有远控会话。`state.json` 仅保存安装标识散列。手机仍采用本机私有设置保存该标识，设备恢复出厂、卸载或清除 App 数据后会按新安装登记。

## 验证与交付

- Node 24 类型检查及 12 项短信接收、远控和浏览器工作台回归均通过。用隔离数据启动实编 Electron 后端和无头 Chromium，验证设备授权、JPEG 显示、点击、仅查看限制、过期画面清除和双端断开。Java 与本地 HTTPS 接收端验证配对、短信到达和审核通知、拒绝未确认画面、确认、帧上传、输入、断开和撤销配对。
- 同页接收和配对更新通过 TypeScript 检查及 13 项回归。无头浏览器在隔离库中通过「远控」页启动接收，解码页面二维码，下载并核对 APK 哈希。模拟手机使用同一个六位口令配对，「请求连接」随即可用，继续通过手机确认、画面、操作和断开联调。手机相机实扫和 Windows 原生窗口待验收。
- 同名选择和交付状态更新通过 TypeScript 检查及 14 项回归。隔离的实际浏览器后端用两个同名配对模拟错误设备轮询、正确设备来取请求、确认后显示画面和断开。Java 联调沿用 APK 1.1.0 的手机协议。Windows 接收网卡测试和 Android 地址解析测试覆盖组网地址。当前电脑未检测到 Tailscale，Android 与 Windows 的真实跨网络接入待验收。
- 设备去重和浮窗更新通过 TypeScript 检查及 15 项回归。覆盖旧凭据撤销、同名设备保留、浮窗续连、点击与滚动、仅查看权限、主动断开和工作台隐藏时结束会话。实编后端和无头浏览器验证跨模块持续显示、断开及 QR 下载。Java 客户端通过了新旧桌面接收端的局域网协议模拟测试。
- APK 1.2.0（版本号 6）的原签名证书、V2/V3 签名、资源对齐和随启动脚本构建的二维码下载均已核验。成品位于同级构建目录的 `android-sms/Rainfall-SMS.apk`，SHA-256 为 `3010cb8d7a140d0beef7e60ef25a7142935979850de4787887d97e2c5cc609a2`。上一版 1.1.0 及校验文件保存在构建目录的 `remote-assist-installation-8c94b0d2/promotion-3b96e9c8/`。
- Windows 原生窗口、Android 真机系统授权、共享实际短信会话、手机触控和前台停止通知等待验收。桌面入口更新按 `docs/release/desktop-delivery-policy.md` 在原生候选验收之后执行。

## 回退

- 手机先断开共享，再退出手机和电脑的远控页面。使用 `android/sms-inbox/Build-Android.ps1` 及现有签名、递增版本号重新打包，可覆盖安装修订版本。回退安装包时，保留上一版及各自 SHA-256。Android 通常不允许直接覆盖安装较低版本。
- 电脑可按上面列出的文件撤回本轮远控改动，保留同一文件的既有业务变更，再用 `Start-Rainfall-Browser.bat` 重建。正式库和接收记录继续保留。
- 旧电脑端的严格格式校验无法读取已登记 `installationKeyHash` 的 `state.json`。确需回退到旧程序时，退出接收并备份该文件，从回退副本的 `devices` 数组移除这个可选字段，保留设备 ID、现有凭据散列、其他配对信息和通知。`arrivals.json` 沿用当前文件。
