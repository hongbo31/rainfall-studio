# 番茄目录上传后的合同流程和执行日志

## 问题定位

- 19:35 的目录批次扫描 10 首，跳过官网已有的 8 首，并为本次上传的 2 首保存了作品回执。清理记录之后紧接着出现 `contract:skipped`。发布任务保存的「是否签署合同＝否」曾被目录发布当作跳过整个合同阶段，因此第 19 步没有执行。
- 这批两张封面在后台持续等待回收。Windows 隔离复测中，旧版用封面路径调用 Sharp 后，Electron 回收报告 `Operation was aborted`。改用文件缓冲区处理相同格式后，原封面可立即回收。音频使用转换后的上传素材，歌词通过一次读取生成上传副本。

## 逐步执行

| 步骤 | 当前行为 |
| --- | --- |
| 扫描与分批 | 读取当前发布账号前缀及艺人匹配的目录。记录本地候选数、材料齐全数、每轮上限、每轮入选数和实际取得回执的首数。遵循设定的上限，余量不足时按实际符合条件的首数提交。 |
| 1–4 | 从番茄创作首页进入「发布作品 → 成品发行」，待表单准备就绪后添加歌曲。 |
| 5–16 | 按艺人配置填写音乐类型、歌曲属性、音频、歌词、作品名、署名、封面、AI 标记及所需版权证明。上传各项材料后核对官网回显，逐首处理。 |
| 17–18 | 点击下一步和确认上传。等待 3 秒并核对授权步骤及完整作品列表，逐首匹配官网回执。音频、歌词和封面进入回收，系统占用时继续后台重试。 |
| 19–22 | 按艺人或账号的签约模式选择独家或非独家，选择「个人」，核对发布平台并进入合同预览。 |
| 23–24 | 核对本轮作品及待生成状态，记录一次生成请求，发起待签合同生成。最多等待 15 分钟，核对原页和它打开的唯一「数据安全验证」页。 |
| 25–28 | 选「否」时，核对同批待签合同回执后继续。选「是」时，打开本批验证页，由本人在官网完成短信验证及签署，核对同一批作品进入审核或上架后继续。当前远控仅同步短信到达记录和业务通知，合同最终接受保留本人确认。 |
| 29 | 继续处理剩余歌曲。恢复已有合同使用原作品 ID 和合同回执。旧执行历史保留原始结果，已上传的旧批次可在番茄「成品发行 → 待授权」按原作品继续。 |

## 涉及文件

- `src/main/fanqie/directory-run.ts`、`src/main/fanqie/plan-directory-publisher.ts`、`src/shared/fanqie-downloads.ts` 与 `src/renderer/components/PublicationTaskEditor.tsx` 区分待签合同生成和本人签署。新建目录批次始终进入合同阶段。任务的「是／否」明确传入目录批次，原有未完成批次沿用保存的执行状态。`src/core/plan-fanqie-directory.ts` 同时保留对提交前断连的识别，核对原执行阶段和日志后允许任务继续。
- `src/main/fanqie/materials.ts` 用缓冲区读取目录封面后缩放及编码，释放原文件路径。系统占用继续使用已有的后台回收保护。
- `src/main/fanqie/directory-trace.ts` 与 `src/main/fanqie/directory-form.ts` 保存步骤、回读、计数和脱敏截图。短暂弹出的报错保留发生时的位置和安全提示。页面关闭或导航后记录未能截图的原因。`src/core/plan-fanqie-directory.ts`、`src/core/plan-center-reads.ts`、`src/shared/plan-center.ts`、`src/shared/schemas.ts`、`src/main/bootstrap.ts` 与 `src/renderer/pages/PlanCenter.tsx` 按原账号和执行 ID 打开日志目录。客户端与浏览器预览共用此入口。
