# AI 作词“结果未知，待对账”排查

更新日期：2026-11-23（北京时间）  
任务：RF-016（只读代码分析）

## 用户现象

任务中心“苏诺之音每日任务”的歌曲步骤显示“AI作词 结果未知，待对账”，并显示“模型用量待核对”。用户反馈等待时间很长。

## 结论

截图对应的状态说明作词阶段已进入持久化 `unknown` 状态。这个状态不是 UI 正在等刷新，也不代表模型仍在后台运行；对账成功或失败前，它可能一直保留。任务中心使用约 4 秒间隔刷新，但刷新只重新读取状态，不会自动恢复未知请求。

状态语义有两种主要可能，截图本身无法分辨：

1. 模型返回的用量/模型信息缺失或不符合计价校验。费用无法确认时，作词任务保存为 `unknown` / `TEXT_USAGE_UNKNOWN`，原预留额度保留。
2. 请求链路异常或应用在请求派发后退出。服务端可能已接受请求，但本机没取得可验证回执；恢复逻辑保守地记为 `TEXT_OUTCOME_UNKNOWN` 或 `TEXT_PROCESS_INTERRUPTED`。

两种情况下，自动重发都有重复生成、重复扣费风险。当前实现因而不自动重试，但也没有同步 API 的自动查询回执路径，状态可能长期停在“待对账”。

## 代码证据

- `src/core/lyric-writing.ts` 的 `record()` 在费用无法计算时保存 `unknown`；服务初始化会把遗留的 `dispatching` 作词任务改为 `unknown`。
- `src/core/workflow/provider-text.ts` 将 HTTP 请求或响应链路异常归为 `TEXT_OUTCOME_UNKNOWN`；DeepSeek/豆包用量字段无法校验时返回 `TEXT_USAGE_UNKNOWN`。
- `src/main/provider-text.ts` 每 2 秒扫描一次，但只挑选 `ready` 任务；`unknown` 不会再次发请求。它将请求异常作为 unknown 回写本地作词任务。
- `src/core/plan-workflow.ts` 在每次计划推进时读取作词任务；未知结果继续保持计划阶段 unknown。没有自动 reconciliation。
- `src/core/plan-center/index.ts` 的通用重试只接受 failed/not_found；provider 作词失败要求新运行，unknown 不能直接重试。
- AI 作词可能顺序执行初稿、评分、最多两轮改写/重评，多个 API 请求的耗时会累加。单个通用 HTTPS 请求有 30 秒超时，但超时后的 unknown 可以一直保留。
- `src/renderer/use-center-query.ts` 的任务中心状态刷新频率约为 4 秒，UI 轮询不是长时间停留的原因。

## 建议

1. 区分“请求已发送”和“发送前失败”。DNS、凭证读取、请求构造等明确发生在 POST 前的错误应记录为未发送/失败，释放预留额度并允许有限重试；POST 后断线、超时等仍须保留 unknown，禁止盲目自动重发。
2. 若供应商提供可查询的请求 ID、幂等机制或用量查询 API，再为其增加只读后台对账；先核实供应商能力，不假设同步 Chat Completions 存在异步任务查询。
3. 对没有可查回执的 unknown，增加明确的人工核对入口，并展示已等待时间、请求是否已派发、供应商请求 ID、用量校验失败原因及预留额度。不要只显示一个长期不变的“待对账”。
4. 将 UI 进度拆成初稿、评分、改写轮次，并显示当前调用和累计耗时，帮助区分正常多轮作词耗时与已进入未知状态。
5. 内容返回但 usage 无效时，评估单独保存可验证的歌词结果与账单核对状态；继续后续生成前必须遵循用户已授权的预算上限，不能把无法核账的费用当成零。
