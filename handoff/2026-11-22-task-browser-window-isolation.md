# 任务中心浏览器窗口独立运行

2026-11-22

任务中心原先已为各任务保存独立的计划执行记录。音乐执行器一次只取一条浏览器任务，账号会话则以账号为单位占用。前一条任务还在等待生成或下载时，后一条任务无法打开自己的浏览器窗口。

## 行为和影响

- 谱乐 AI 和苏诺之音按任务关联的计划执行 ID 启动独立浏览器进程。不同任务可同时打开窗口，并沿用账号管理中已保存的登录状态。每个窗口使用自己的临时浏览器数据和页面。同一任务需要继续下载时，使用其窗口和原歌曲回执。
- 同账号的窗口可以并行填写表单。生成提交到歌曲归属确认这一段按账号排队，防止共享歌曲列表中的其他任务结果被误认领。已有去向未明的同名歌曲时，新提交会提示核对原任务。谱乐确认回执后可与下一次提交并行下载，苏诺之音在当前页面保存原 WAV 后释放队列。
- 停止任务会中止它拥有的浏览器步骤及窗口。手动关闭单个任务窗口也只会处理对应执行。已提交的请求由原任务保留回执或待核对状态。
- 一个任务内的关联计划按所选顺序执行。两个任务引用同一条计划定义时，沿用这条计划的排队规则。番茄等发布环节继续使用对应账号、文件认领、发布回执及合同确认流程。本次窗口隔离覆盖歌曲生成。

## 涉及文件

- `src/main/plan-pule.ts` 管理各执行的调度、中止和同账号提交队列。`src/main/task-music-windows.ts` 和 `src/main/browser-accounts.ts` 管理临时窗口及登录状态的读取。`src/main/bootstrap.ts` 将浏览器版和 Windows 客户端的停止操作接入同一执行器。
- `src/main/pule-browser-page.ts` 和 `src/main/suno-cn-browser-page.ts` 在表单就绪后和点击生成前等待授权。`src/core/plan-pule.ts` 校验执行范围及歌曲回执归属。`src/renderer/plan-execution-labels.ts` 显示窗口及回执状态。
- `tests/plan-workflow-refactor.test.mjs` 和 `tests/pule-browser.test.mjs` 覆盖第二个同账号窗口打开、独立停止、复用已保存登录状态、浏览器存储隔离和回执去重。

## 回退

还原本轮列出的变更后从原入口重新构建。现有计划、任务、账号和作品可直接读取，数据库无需迁移。已经产生的歌曲回执保留在原执行记录内。
