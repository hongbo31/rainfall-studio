# 「日常」计划评分格式修复

2026-11-21

## 原因

北京时间 21:15:04 启动的「素素每日任务」中，「日常」的前两轮已完成，第 3 轮于 21:29:20 停在 AI 作词。DeepSeek `deepseek-flash` 已生成并保存 5 稿。第 1 至 4 稿分别为 85、68、81、81 分，第 5 稿未取得有效评分。同期「番茄音乐平台上传」独立完成。

只读检查确认，作词任务进入了已结算的评分响应处理，返回内容可解析为 JSON，程序保存的错误分类为 `fields`。本地请求绑定对应已保存的第 5 稿。旧解析要求严格匹配评分对象及五个分项，多余字段和分项类型或范围异常都会拒绝整份评分。历史记录没有响应正文，无法确定模型当时返回的具体字段。隔离测试复现了完整分项因额外字段被拒绝，以及已有高分稿时因后续分项缺失而整轮失败。

## 改动范围

- `src/core/lyric-writing.ts` 从评分响应读取所需字段。完整五项按原范围校验并由程序加总，接受可明确转换的分项整数字符串，忽略多余说明和多报的总分。只有总分的兼容格式仍校验整数、语种核对和评语。请求与稿件绑定、模型用量、预算和停止校验继续生效。
- 同一核心在计划的改写评分格式不可用、且已有稿件绑定一致并通过语种核对的评分时，保留未获评分的草稿及错误分类。还有改写次数时从有效最高分稿继续，达到改写上限时采用有效最高分稿。整个过程使用原有改写次数和调用预算。稿件绑定异常或没有可采用的评分时，保留执行记录和已存稿。符合原有校验的任务可从计划中心确认重评。
- `src/shared/lyric-writing.ts` 增加可选的分项错误分类和稿件诊断字段。`src/renderer/components/PlanLyricReview.tsx` 在「查看作词评分」中显示哪一稿的分项无法校验。旧库中的评分和错误记录沿用原有格式，无需迁移。
- `tests/lyric-writing.test.mjs`、`tests/plan-workflow-refactor.test.mjs`、`tests/plan-workflow-ui.test.mjs` 覆盖评分兼容、上限校验、异常后的续写和选稿、稿件错绑及诊断显示。

## 验证

在源码同级的 `rainfall-studio-build/lyric-review-format-303fd012` 中构建和测试。改动前，四项新增断言复现了拒绝有效数据、分类过宽、提前阻塞及稿件错误分类。改动后结果如下。

| 范围 | 结果 |
| --- | --- |
| AI 作词与计划工作流 | 63 项通过 |
| 计划中心与任务中心 | 28 项计划核心回归及 22 项任务核心和页面结构测试通过 |
| 浏览器 | 现有启动脚本以 `-BuildOnly` 在隔离工作区构建成功。HTTP 会话和无头渲染共 5 项通过，包含评分详情和重评确认 |
| Windows 客户端 | TypeScript 检查、Main、preload、Core 与渲染构建及产物语法检查通过。Electron 的 Node 模式验证共用 Core 对原执行记录的恢复 |

使用只读查询取得本次运行所需记录，仅在内存库调用原有重评入口，并分别在 Node 与 Electron 的 Node 模式核对。模拟有效评分时，第 3 轮重评的是已保存的第 5 稿。模拟分项持续不全时，完成剩余 1 次改写后选择已有的 85 分稿。两种情况均在原执行中推进到第 3 轮的音乐提交前，前两轮、父任务历史及番茄上传记录保持原样。

真实文本模型、音乐生成和 Windows 原生窗口尚未验收。实际执行仍显示原记录的失败状态，生产库仅作只读查询。未更新桌面入口。

## 恢复与回退

- 浏览器下次从同一个 `Start-Rainfall-Browser.bat` 启动时会从更新后的源码构建。进入「计划中心 → 日常 → 详情」，选择 11 月 21 日 21:15 的执行，在第 3 轮选「重新评分（按服务计费）」。桌面端也可从「任务中心」的「日常 → 查看执行」进入同一记录。确认后使用原稿继续，随后按原计划处理这一轮。父任务的「部分失败」是当时记录的总结果。
- 回退时撤回本轮所列源码和测试差异并重建。增补诊断是可选字段，可继续读取现有作品、评分和执行历史。Windows 桌面入口依现有交付验收流程切换。
