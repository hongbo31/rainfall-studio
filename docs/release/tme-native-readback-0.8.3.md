## 可复现缺陷与修复范围

| 观测 | 原因与处理 |
| --- | --- |
| 点击后立即报告找不到归属选择器，但随后出现同一 Chrome 对话框 | 单次点击后等待归属、进程和空选择检查通过；只重读，不重开或重选 |
| 目录跳转 350 ms 后仍读到旧目录 | 单次目录导航后等待同一对话框的准确目录，保持前台、所有者、空文件名和空选择检查 |
| 字段或开关已更新，立即回读仍报失败 | 单次写入后有界重读；超时保持未知结果，不自动重写 |
| 选中“完整版”后出现父子同名 RadioButton | 只折叠已证明祖先关系的镜像，独立重复控件继续拒绝 |
| 翻唱开关出现父子 Button 镜像，false 被读成 null | 使用同一祖先归一化，保留明确的 false；独立开关歧义仍拒绝 |
| 上传后只有基本曲目卡片，完整解析器读取不存在的歌词／专辑字段 | 返回可读的部分表单与 metadataExpanded=false，在元数据写入前明确阻止，不把部分填写当完成 |
| 多个歌名输入框或折叠的已有曲目卡片被回退为上传入口 | 多歌名明确拒绝；更换音频／曲目编号／正数首数等已有曲目证据不可读时明确拒绝，在实际上传入口回放中证明未到达上传点击 |
| 选择器地址栏暂缺时，文件名或选择项安全错误可能被等待掩盖 | 实际 Picker-Proof 先检查文件名和选中项，再判断地址栏瞬态；组合状态回放证明第一次读取立即拒绝 |
| 辅助验收脚本期待“修改图片”，实际为“更换图片” | 这是本轮辅助脚本错误；基线客户端本来已使用“更换图片”。后台修复不新增未经观测的别名，只加强按钮／裁剪状态证据 |

`AUDIO_UPLOAD_CONTROL_NOT_UNIQUE` 的首次原因是控件位于小窗口视区外；`ACTIVE_TAB_REQUIRED` 曾与后台可访问性有关；`EXACT_CREATED_TAB_REQUIRED` 来自辅助恢复脚本。这些不应误报为权限拒绝，也不应通过猜测窗口或放宽所有者检查处理。本次没有新增自动激活窗口能力。
