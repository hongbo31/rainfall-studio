# 腾讯音乐人草稿通道设计

目标：在当前发布中心中实现歌曲选择、资料预检、真实账号核对、浏览器表单映射、附件上传、保存草稿及回读。第一轮真实操作止于提交审核之前。当前未选择正式试传作品，因此本阶段只实现及验证本地/fixture 主流程。

## 已知事实与证据边界

- 基线为私有仓库 main `f6b2e08`，仅继承干净发布历史；使用独立本地分支，不推送、不打包 EXE。
- 当前主机确认为用户指定的90VC。初次检查没有用户浏览器进程；随后用户登录，已通过 Windows 原生只读窗口截图观察 Chrome 的腾讯音乐人首页。页面显示个人入驻卡片“审核未通过”，这不能代替具体作品状态或上传表单校准。没有点击、导航或修改用户页面。未访问其他电脑。
- 官方入口 https://y.tencentmusic.com/ 可访问，但公开读取未提供授权上传 API 文档；不将其推断为不存在 API。优先保留未来获批 API 适配路径。
- 用户提供的字段描述为作词、作曲、是否 AI、AI 工具、生成日期、歌词（10–20000 字）、音乐人说（可选5–300字）、创作证明；这不能代替登录后 DOM、保存草稿行为、附件要求及身份标识的现场校准。

## 分层与数据

Core 的 TmeDraftService 管理不可变资料快照、预检、防重指纹、步骤检查点及审计；暂用主 SQLite 的 settings 命名空间 `tme-draft:*`，不改变既有 SQL schema，原始歌词、清理预览和确认版本分别保存。主程序的 TmeCoordinator 串行执行浏览器任务，renderer 不能伪造上传或账号回读结果。

BrowserPort 是最小 UI 能力接口：观察账号/表单、回读远端草稿/附件、填字段、逐项上传、保存草稿。真实驱动通过已安装的 playwright-core 操作正常浏览器 UI；只连接用户明确选择且已经允许连接的本机浏览器，不创建调试端口、不启动/重启其浏览器、不读 Cookie/token/storageState、不请求私有接口。没有可用授权会话就阻塞。账号按平台可见标识、设备及会话绑定，动作前重读身份；不因本地账号备注认定授权。

生产页面契约默认未校准，真实写操作拒绝执行。用户提供90VC已登录页面并选择试传素材后，先只读确认实际 DOM、账号标识、草稿按钮和附件状态，再允许明确范围的草稿操作。fixture 契约仅用于隔离测试，界面标记为模拟，不能产生真实授权状态。

## 预检与歌词

必须选择托管库音频/封面，用户确认版权、作词/作曲姓名与本人身份、AI 声明、工具及日期、歌词与音频一致；创作证明只使用用户明确选择的已有材料，绝不生成证明。AI 否/未知不能被音频导入自动改成否；作者身份默认未确认。

清理仅处理独占一行的已知生成指令标签（如 [Verse]、[Chorus]、[Instrumental]）与换行格式，保留原稿。内嵌标签、未知标签、有内容的括号行均保留并提示复核；不改字词、不自动断句。清理前后预览确认与音频匹配确认绑定当前歌词哈希，编辑后失效。

## 防重、恢复与审核边界

指纹包含平台、已确认远端身份、录音哈希、资料快照。相同任务返回已有记录；同录音同账号不同资料也提示已有任务，不能用改标题逃过防重。每个动作前持久化检查点，成功后存远端附件标识/证据。进程重启、超时或未知结果首先回读远端；未证明未上传不得重传。已确认音频成功、封面失败时，仅恢复封面及后续步骤。

页面契约变化、账号切换、会话丢失、验证码、风控或无法证明的远端状态均明确阻塞。超时不等于失败或成功。保存草稿只有回读到一致账号、草稿ID和资料/附件证据才标记成功。MVP 不注册提交审核 IPC；接口保留未来提交审核及结果同步的类型，但当前实现拒绝提交。备份恢复必须清除浏览器执行授权，并将未完成任务置为需远端核对。

先写失败测试，再实现。覆盖作者不默认勾选、歌词原稿保留/清理确认失效、边界长度、账号切换、防重、并发、超时回读、已上传不重传、重启恢复、页面变化、保存后回读失败与审核禁用。用本地页面 fixture 验证真实 DOM 驱动，并用独立 Electron QA 目录验证交互和截图；不访问无关用户文件，不运行或中断现有客户端。最终保留本地提交、证据和真实材料/账号/页面校准阻塞清单。
