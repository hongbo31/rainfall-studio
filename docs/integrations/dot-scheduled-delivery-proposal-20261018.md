# dot scheduled lyrics and cover delivery — design proposal

Status: design only, not implemented or end-to-end connected.
User scope: dot creates one set of lyrics/style prompt/cover per day (provisional Asia/Shanghai09:00, configurable); fixed software receives it. Never replace dot with Work/CLI/DeepSeek generation, never automatically create paid music or publish. Formal installed data stays unchanged until validation and a separate upgrade decision.

## Current facts

- Existing inbox v1 accepts text only. src/shared/inbox.ts and src/shared/creation.ts are the complete authoritative schemas. docs/integrations/dot-minimal-inbox-example.json is a complete valid example.
- Envelope: schemaVersion=1,batchId,createdAt,targetWorkspaceRef,items(1–20).
- Each item: externalItemId,revision,parentRevision,artistRef,seriesRef,draft,provenance.
- draft: title,topic,storyBeat,language,style,instrumental,sections,hook,vocalPlan,musicPrompts{suno,yourmusic},continuityNotes. Both music prompt objects require positiveStyle,negativeStyle,durationTarget,voiceArrangement.
- provenance requires producer,model(nullable),promptVersion(nullable),generatedAt.
- IDs are bounded ASCII, content strict UTF-8, total JSON <=1MiB. Unknown fields are rejected; adding cover/image URLs to v1 is not supported.
- GUI: AI聊天创作 → 文本收件箱 → 配置本地收件通道. Core checks configured workspace/artist/series aliases. Formal channel currently unconfigured.
- Root is Main-controlled <dataRoot>/production/inbox-v1; incoming,receipts,processed,rejected. Existing Core tick scans about every5seconds while client runs. No public listener or model call.
- Isolated configured root: output/daily-lyrics-audit-20261018/isolated-local-1792346798887/production/inbox-v1. workspaceRef=rainfall-personal, artistRef=creator, seriesRef=null. A scan succeeded, no actual dot payload imported.
- Import commits drafts/textCandidates with local checks and evaluationState=model_pending. It does not connect these items to model scoring or automatically approve music/publication.

## Transport capability discovery (2026-10-18)

- Google Drive connector harmless reads succeeded; list_drives returned no shared drives and folder search Rainfall returned no results. This demonstrates cloud read connectivity, not a selected writable delivery folder.
- Local environment has C:/Users/PUBLIC_USER/OneDrive with old directory metadata. No OneDrive/GoogleDriveFS/Dropbox/Box process was observed. Folder presence alone is not an authorized working sync bridge.
- Source scan found no installed Google Drive/OneDrive/Library cloud-poll adapter.
- Library artifacts can be copied by authenticated conversation tools. No standalone authorized Library polling API/credential is available to the local client. Signed transfer URLs are temporary; they are not a reliable permanent daily source.
- No public service, OAuth client, credential, file-share permission, shared folder or new scheduler was created.

## Recommended transport

Reuse an existing approved cloud folder synced to this Windows host. dot writes generated bytes and manifest to the cloud folder; the installed sync client handles authentication/download. A fixed local bridge reads only the configured project subfolder and writes validated content to the private client data root. Receipts sync back through a separate receipts subfolder. No daily Work session moves files.

Cloud-side and local-side access must be tested together. Recommended available starting point: Google Drive cloud connector, after user selects a project folder and confirms an already-installed local sync client. If no sync client exists, installation/login needs user action/approval; do not install it or create API credentials implicitly.

Alternative: user identifies an already-authorized OneDrive/NAS/SMB project folder with an available cloud write path. Current OneDrive directory alone does not establish that path.

Minimum unresolved user action: identify one shared folder reachable by BOTH dot's authorized cloud tools and a running Windows sync client (or authorize one-time setup). Parent coordinates that choice and cloud generation. Do not claim cloud-to-Windows delivery before a real manifest+image arrives and its receipt is observed back at the producer.

## Minimal cover transport wrapper (proposed, not current inbox schema)

Keep textPackage schema v1 unchanged. Use a separate project delivery directory:

deliveries/<deliveryId>/text.json
deliveries/<deliveryId>/cover-<sha256>.png
deliveries/<deliveryId>/manifest.json
deliveries/<deliveryId>/READY.json
receipts/<deliveryId>.json

manifest:
{
 "deliveryVersion":1,
 "deliveryId":"dot-20261019-0900-001-r1",
 "createdAt":"2026-10-19T01:00:00Z",
 "targetWorkspaceRef":"rainfall-personal",
 "text":{"file":"text.json","sha256":"<64 hex>"},
 "images":[{
   "externalItemId":"dot-original-001","revision":1,"role":"cover",
   "file":"cover-<64hex>.png","sha256":"<64 hex>",
   "bytes":12345,"mimeType":"image/png","width":2048,"height":2048,
   "provenance":{"producer":"dot","model":null,"generatedAt":"2026-10-19T01:00:00Z"}
 }]
}

READY contains deliveryId and manifestSha256. Literal hash placeholders are explanatory and cannot be accepted as real data. File basenames are plain filenames, never arbitrary paths/URLs. Every item can have one cover in the minimal version; new variants use a new revision. Image creation must produce actual image bytes; a prompt alone remains cover_pending.

## Fixed receiver behavior

1. Scan configured shared project folder on startup and about every30seconds; no model process. Only READY deliveries enter the receive queue. Images/text may arrive out of order via sync; missing bytes stay waiting and do not become success/rejection merely because the manifest arrived first.
2. Stable identity = deliveryId + externalItemId + revision; same identity/hash reuses the same candidate and asset. A conflicting hash is quarantined, never overwrites a prior accepted receipt. Date/time are provenance, not sole deduplication identity.
3. Copy into a private staging directory using unique .partial files. Check manifest hash, bounded size, UTF-8 schema, mapped artist/workspace/series, and each image's exact SHA/size. Decode actual image bytes (existing sharp dependency) to verify supported PNG/JPEG/WebP, actual dimensions and sensible bounded pixel count; file extension alone is insufficient.
4. Require all required cover and text assets to verify before marking the delivery imported. Store immutable image bytes by content hash; use the existing InboxService inside the same metadata transaction with the text candidate and cover-version relation. Any failed transaction leaves no accepted receipt; immutable orphan bytes are harmless and can be retried.
5. Persist receipt after commit via atomic rename/fsync. Rebuild receipt from DB after crash. Receipt records independent candidate ID, cover asset ID/hash, validation results and imported_at. External source/model remains declared-unverified, never proves copyright or model identity.
6. Transient missing/sync/IO failures retry with 30s,1m,5m,15m bounded backoff; no regeneration and no model charge. Permanent schema/hash/identity conflicts enter rejected/quarantine with explicit reason. User can retry the same original delivery; it must reuse IDs.
7. On restart/offline recovery scan all unacknowledged READY packages, not only today's date. Retain a bounded per-scan queue; older completed days are not regenerated or silently discarded. Machine off means cloud retains packages, then receiver catches up after boot/sync. Receiving while application is fully stopped needs a separately approved always-running helper/autostart; it is not provided by the current client.
8. Local structural/range/provenance/image checks are labelled rule_based. Model evaluation stays model_pending/not_authorized. No model quality score is fabricated from structure checks. dot may provide a declared self-review, but that is not independent evaluator output.

## Smallest real acceptance

Parent supplies one actual dot-created v1 text payload and actual original cover bytes through the chosen shared transport. Receive and verify hashes; show title/lyrics/prompt/cover from same revision; observe exact receipt back in shared storage. Re-deliver identical package, out-of-order assets, missing cover, corrupt image/hash, interrupted copy, offline restart: no duplicate candidate/cover, no false success, original package recoverable. Verify zero Work/CLI/DeepSeek/music/publishing calls.

After that one end-to-end transfer passes, parent can enable its provisional daily09:00 generation schedule. No schedule was enabled by this design work.
