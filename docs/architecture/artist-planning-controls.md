# Rainfall Studio：艺人、每日计划、额度与异常处理

2026-10-15 补充决策。与 [共享契约](contracts.md)、[持久队列](batch-publishing.md)、[源码构建与运行说明](../../README.md) 一起执行。本文件确定业务规则，尚未实现。继续使用 **Rainfall Studio / rainfall-studio** 暂定名称，保留原型已有中文文案及已认可的深色暖紫布局，不从参考文档引入新品牌或管理员身份。仍以单机 Windows 客户端为主，不新增 Web 服务、云调度、团队 RBAC 或分布式集群。

## 1. 艺人与平台账号分离

ArtistProfile 管理艺名、简介、创作默认值及封面风格；PlatformAccount 管理平台身份、remote subject、授权 scope、令牌引用和能力。账号不以 artist_id 直接归属艺人。ArtistAccountBinding 连接两者，带目标平台、内容类型、允许操作、外部艺人标识（可空）、验证来源与状态；一个艺人可绑定多个账号。共享发行账号可在平台允许且有证据时绑定多个艺人，不能由同名自动建立绑定。

绑定权限只限制本地操作，不授予第三方权限：有效权限 = 本地绑定操作 ∩ 账号 scope ∩ 应用获批能力 ∩ 平台当前规则 ∩ 本次授权范围。默认新绑定只允许本地准备，真实提交需要经过验证。每次执行校验 workspace、artist、binding、account、remote subject、内容类型；切换艺人不切换运行中任务的账号。解绑/撤权暂停关联未提交操作，已提交历史保留；重新授权到不同 subject 必须新建身份绑定并使旧批准失效。

账号隔离是数据库、凭据、队列、预算、日志的隔离，用于防串号。禁止指纹伪装、浏览器环境伪装、免费账号池、规避限流或平台多账号限制。系统浏览器 OAuth 不读取浏览器 Cookie。首版没有团队成员与角色权限界面；这不构成同一 Windows 用户下的强安全隔离。

## 2. 默认创作配置与单曲覆盖

CreationDefaults 包含 genreIds、voice（male/female/duet/instrumental）、lyricTone、bpmRange（整数 min/max，20≤min≤max≤300）、coverStyleBrief。可附 language/mood/duration，只有适配器明确支持时才映射为平台参数，不能承诺精确控制音频 BPM/时长。

解析顺序：应用基础值 → 艺人配置版本 → 每日计划显式覆盖 → 单曲显式覆盖。未设置表示继承，空数组/空文本只有字段允许时才代表清空；重置为继承必须独立动作。纯音乐时歌词字段可保存但不作为演唱指令发送。UI 对每字段显示来源与最终值；单曲覆盖不回写艺人默认。开始一次运行时冻结 resolvedConfig、各来源版本和 hash；修改艺人默认或计划只影响未来运行，不能静默改变已有候选、提示词或批准快照。

默认值与歌词、故事、系列上下文一起构成本地提示词；Codex 封面入口导出任务文本并导入结果，不提供假想免费图像 API。作品可以改艺人，但涉及发布中的版本需新快照、重新检查绑定及权益，保留旧归属历史。

## 3. 手动创作与每日计划

“创作”页面提供两个入口：立即手动创作、每日创作计划。两者共用 CreationRun 与步骤执行器，产物均入同一作品库；计划不是另一套发布系统。计划表单包括艺人、启用状态、IANA 时区、每日本地时间、故事/系列选择、参数覆盖、候选上限、成品目标、生成成本上限、工作流检查点与目标账号映射。启用计划只允许其保存的范围，不授权未知价格、未获批接口或真实投稿。

首次创建计划显示下三次计划时间及 UTC 值。到点通过 unique(plan_id,local_date,slot)，schedule_revision单独留档 创建一个 run；slot 首版固定 daily。计划编辑在事务中关闭旧 revision 的未来触发，已排队/运行实例不被替换。同一天已创建实例后修改时间，不自动多生成一轮；显式“再运行一次”属于独立手动 run，仍受同日所有预算约束。

首版调度只在客户端打开时运行；关闭即不调度，不安装系统服务、不创建 Windows 计划任务、不隐藏常驻。唤醒/重启显示错过的计划：不自动追补历史日期，不积压收费任务。用户可明确选择补跑一日，固定原计划日期用于追溯，但生成成本和候选额度归实际执行日、成品归原计划目标日；界面同时显示两日期。未来若要求关机时运行，另行设计明确授权的系统调度，不悄悄改变首版行为。

DST：本地时刻不存在时取该日时区规则的第一个有效时刻；重复时刻只取第一次 offset。存 resolved UTC、offset、timezone 和规则解析版本。通过注入 Clock 与时区解析器测试，不能依赖机器当前时区；更换时区只影响未来 run，不移动已占用账目。系统时钟大幅跳变/回拨后重新检查唯一键和到期集合，不连发所有错过任务；每计划最多一个活跃 run，全局并发仍按队列限制。

本地模板提示词、已导入素材整理、封面本地排版可以自动执行。生成 API 未接入时 run 停在“等待官方生成后导入”，显示操作入口与待导入候选，不生成虚构音频。不能为达成日目标重复无限生成；候选、成本任一到顶即停止，未达成目标给出差额和原因。

## 4. 三类账目与计数规则

三类独立展示、独立约束，不能用“今日额度”一个数字替代。平台真实余额未知时为 unknown；本地上限、预计值、实际值与外部导入来源分别显示。所有金额/credits 使用整数最小单位，不能跨货币相加。

| 账目 | 计数对象 | 预占与结算 |
|---|---|---|
| 生成成本与候选预算 | 按 workspace/provider/account/unit 的成本上限；按计划/艺人/实际执行日的 candidate slots 上限 | 调用前原子预占最大可扣成本及服务一次返回的最大候选数；同 operation 重试不重复预占。确认成本后结算，确认未扣费才释放；结果未知保留。候选返回后按唯一 provider job + output ID 入库计数，失败/退款不删除实际已产出候选记录 |
| 成品目标 | 每日计划期望完成的独立 work 数量 | 目标是产出指标，不是付费余额。只有必需音频、歌词或纯音乐声明、所选封面、来源/权益记录齐全且通过配置的成品检查点，才记一个 completion event。A/B、重排封面、同曲多平台不增加成品数；撤销成品资格记反向事件，同一 work 在一个计划内仅分配到一个目标日；移动归属需撤销原事件并留审计，不能跨日重复计数 |
| 平台账号提交配额 | 账号＋目标平台＋内容类型＋配额时区日的提交单位；如发行路线另有限制，再加路线账号配额桶 | 预检可估算，真正领取执行时原子占额。一次正式被接受的投稿消耗一次；安全重试沿用同 reservation。UNKNOWN 保留；确定未提交且取消才释放；审核驳回、下架或删除不退还已接受投稿次数 |

生成候选预算规则：若平台一次返回两版本，发起前预占2；剩余1则不能发起该请求。最大输出数或最大可扣成本无法可靠界定时，禁止自动付费执行，走人工生成/导入。明确服务成功却无输出时按实际收费结算，候选占额经核对释放，并记录异常；服务返回超过声明上限的输出全部留存、显示预算超额并停止新调用，不丢弃已付费资产。素材导入不虚构平台扣费；手动导入候选可计入计划候选目标，但标记 imported，不消耗不存在的 API 费用。

提交配额示例：同一曲向网易云、汽水、QQ、酷狗、抖音各投稿，分别占五个目标账号桶，成品仍为1首。如果已验证 TME 一次提交覆盖 QQ+酷狗，则占两个目标配额各1和一个路线请求额度1，外部 commit 仅1次；未知结果时三个预占同时保留，不能因一个目标通过就重复提交另一目标。若平台有不同计费/限额口径，以有版本证据的 QuotaRule 映射，同时保留本地目标计数供用户核对。平台未知限制不得显示为“官方允许每日N首”，只能设置保守的本地上限。

跨日：每桶保存 timezone、local_date、UTC起止、rule_version。午夜创建新桶，不归零旧账。尚未越过远端边界的预占在执行前过期重验，跨日时同事务释放旧预占、尝试占新桶；新桶不足就停。已发出/结果未知的操作继续占原桶；若次日安全重试将再次发请求，还需占新日的风险额度，旧未知预占在核对前不释放，避免跨日绕过上限。最终按可信 accepted_at/charged_at 对实际日结算；平台时间未知保留原预占与争议标记，不猜测日期。晚到结算导致超额则阻塞后续任务，不倒改历史。预算收紧不会取消已发生费用，先阻塞新操作并显示在途预占。

多桶预占与 operation intent 必须在同一 SQLite 事务内完成，任一不足全部回滚。账本 append-only，每笔以 operation_id + ledger_kind + bucket_id + event_kind + source_event_id 去重；reserve/settle/release/adjustment 不互相覆盖。成本可能发生在生成、封面或上传阶段时共用货币账本但保留 purpose；候选 slots 仅音乐候选，提交配额仅投稿，不能混淆。

## 5. 工作流检查点

流程：解析配置 → 故事/歌词/提示词 → 生成或等待导入 → 候选选择 → 素材整理/封面 → 成品检查 → 发布预检 → 发布确认 → 提交 → 审核观察 → 上线观察。每步保存输入 hash、输出引用、费用证据、状态与下一步条件。

CheckpointPolicy 对歌词确认、候选选择、封面确认、成品确认可选 manual/automatic；默认自动完成本地准备、整理，候选可按明确的用户规则选择，无法确定则人工选择，不凭空声称 AI 判断质量。发布确认默认并且首版强制 manual。真实付费生成必须有单次或计划级明确 CostAuthorization，包含 provider/account、金额/候选上限、时间范围、艺人/计划与规则；创建计划、账号登录或本地自动模式不等于付费批准。未接入的步骤保持 waiting_external/manual_action。

平台许可、账号身份、有效绑定、权益/AI声明、文件完整性、预算配额、防重与 UNKNOWN 核对是不可关闭的执行门禁。把某个创作检查点改为 automatic 不绕过这些门禁。策略编辑只适用于未来步骤，需要重新生成策略快照；不能追认已经越界的操作。

未来自动发布仅预留 PublishGrant 契约，首版 UI 不提供可生效的开关。授权必须显式限定艺人/计划、账号/平台/内容类型、可见性、时间窗/时区、每日及总次数、费用上限、允许内容规则和撤销方式；Core 验证具体不可变快照符合授权，记录派生授权证据，绝不由 worker 伪造人工批准。范围外或内容规则无法机器判定时回到人工确认。恢复备份、身份改变、授权到期或撤销立刻停止后续副作用；已提交内容不自动撤稿。

## 6. 异常中心与逐步骤恢复

在总览显示异常计数，在任务/发布中心提供统一异常视图，避免新增庞杂顶层导航。每条展示艺人、计划/作品、账号/平台、失败步骤、错误原因/发生时间、已产出资产、已花费/预占/未知费用、远端是否已提交（是/否/未知）、安全动作与证据来源。

run_steps 持久化 pending/running/waiting_confirmation/waiting_external/succeeded/failed/unknown/skipped/cancelled。步骤输入 hash + adapter profile + operation key 定义重用边界。重试只选择失败且明确安全的步骤；成功的付费生成、候选下载、封面、转码与已提交目标复用已验证输出，不重跑整条链。若输入版本改变，建立新的明确步骤/快照，提示新增费用和失效的下游输出；旧输出不删除。UNKNOWN 必须先核对，不能加入“全部重试”。

例如生成已付费成功、封面导入失败：保留音频与费用，仅重做封面；上传已完成、提交响应丢失：停在待核对，不重新上传/提交；审核驳回：展示原理由并进入修订/人工处理，不网络重试。账号撤权、预算不足、缺素材、等待人工均为阻塞/待处理，不假报系统故障。每个恢复动作写审计与操作结果，重复点击返回同一操作。

提交、审核、上线是三条独立证据：submission=SUBMITTED 只表明远端接受；review=approved 只表明审核通过；publication=live 必须有独立的可用官方或用户录入上线证据、时间和链接/remote id。未提供上线查询的接口始终显示“上线状态未知”，不得通过等待时长或审核通过推断。历史观察 append-only，乱序事件不能把新状态倒退；平台明确撤回/下架另有事件与原因。

## 7. 补充验收用例

1. 两艺人、三账号（含共享发行账号）绑定隔离；伪造 artist/account/binding IPC 被拒绝；解绑后未提交暂停，历史仍可追溯。
2. 艺人默认→计划覆盖→单曲覆盖逐字段可见；修改默认不改变运行中的快照；非法 BPM 拒绝。
3. 手动和每日计划均产出同类型作品；应用关闭不运行；错过两天不自动付费追补；DST两种转换、时钟回拨、重复tick、修改时间均不重复创建日实例。
4. 一次返回两候选、只余一个slot则阻塞；回执丢失不释放成本；同provider事件不重复记账；成品一首多版本/五平台仍只记1。
5. 多桶预占部分不足全部回滚；跨午夜未发重新占额、已发未知保留风险额度；TME合并单位只commit1次，目标桶各占1；驳回不返投稿配额。
6. 默认发布必须确认；自动整理不授予付费权；过期/撤销/跨账号/越费用上限授权被拒；备份恢复不恢复付费/发布授权。
7. 成功生成后封面失败，仅封面重试且生成调用次数不增；提交未知不能批重试；审核通过而上线未知时三个列显示不同状态。
8. 真实封面、音频、平台 API 缺失时显示等待导入/接入，不伪造运行成功；生产模式所有未授权传输计数为0。全部测试使用隔离QA库和fixture，真实接入另需授权。
