# 当前候选原生验收与正式升级的最小操作

本轮保持后台，不执行以下可见操作。父会话可用这份清单统一协调一次用户窗口；它不包含平台创建、上传、接受条款、发布或付费生成授权。

1. **确认安全时间与原程序状态。** 只检查 Rainfall Studio 当前窗口、实际进程、同一桌面快捷方式及 `verified-desktop.json`。如窗口有未保存内容，先让用户保存并正常退出；不强制结束进程。记录旧版本、EXE、sourceCommit、dataRoot、指针及程序哈希。
2. **做可回滚备份和基线。** 对权威 dataRoot 的 SQLite 做一致性快照，备份媒体及原指针/启动脚本/快捷方式。单独记录作品 ID、作品/版本数量、已选择 A/B、音频/封面 SHA256 与可读性。保留凭据原位置，不复制或导出 vault、Cookie、浏览器 profile；不启动正式计划或业务 tick。
3. **只在隔离副本打开当前候选。** 使用备份副本作独立 dataRoot，显示一个客户端窗口。核对窗口版本与实际 EXE/commit/dataRoot；查看旧作品 ID、歌词和封面，实际播放一个已存在的 A 音频，切到存在的 B 音频再播放。没有真实 B 就记录缺项，不能假播。打开本轮改动的计划/封面恢复入口，确认布局、按钮和状态。检查原生 `media://` 读取、控制台/诊断错误以及退出重开后的版本/选择持久化。不在该步骤连接或操作第三方发布页。
4. **同一桌面入口切换和复验。** 第3步通过、原库/媒体兼容且备份完整后，原子切换受信程序指针，dataRoot 仍指向原权威位置；保持同一 `.lnk`。从这个快捷方式实际启动，核对版本、commit、EXE、dataRoot、原作品 ID/音频/封面；再次点击同一快捷方式，确认聚焦既有窗口且只有一个拥有数据根的实例。最后按用户选择正常关闭或保留窗口。
5. **失败即保留或恢复旧入口。** 切换前失败不改正式入口；切换后失败只恢复备份的指针/脚本/快捷方式，不删除新旧数据、不倒灌覆盖新作品。保存截图、实际进程/版本路径和验收报告。

最小可见动作是“打开隔离候选一次 → 看旧作品及封面 → A/B各播放一次（存在时）→ 退出重开 → 同一快捷方式启动与再次点击”。备份、哈希和指针草案可在后台准备。用户窗口可用前不启动；本轮没有原生验收通过或正式升级成功的结论。
