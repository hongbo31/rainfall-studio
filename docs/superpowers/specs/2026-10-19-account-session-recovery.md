# 账号绑定、登录有效性和发布恢复边界

适用当前 0.12 集成设计。本文区分已具备的通用安全边界和待实现的账号连接状态，不把既有本地备注记录当成官方绑定。

## 身份与登录是两个维度

- bindingState: unbound / pending_verification / bound / revoked / unsupported。
- loginState: unknown / login_required / valid / expired / identity_mismatch / unavailable。
- bound 只在正常官方会话内读到可验证 remoteAccountId、remoteArtistId 和来源证据，并由用户确认本地 artist mapping 后成立。登录有效必须另有最近一次会话验证；发现页面或同名艺人不能充当证明。
- 绑定元数据包含平台、账号/艺人稳定ID、显示名、本地艺人ID、证据引用、修订号、验证时间、会话引用。只存正常隔离环境的 opaque ref，不读出 Cookie/Token，不复制到云端或报告。服务能力不支持读取稳定身份时始终待核实/未接入。
- 旧 accounts/bindings 保留；local_only 不自动提升到 bound。一个本地艺人可关联多个平台的明确远端身份，不用显示名合并。

## 用户界面

发布平台设置中提供明确“绑定账号”入口；适配未完成的平台显示“未接入”，不得打开空页面后报成功。已绑定账号各自显示“已绑定 · 登录有效/待核对/需重新登录/身份不一致”。多个账号分别管理，不让一个过期账号冻结无关账号。

优先复用用户已授权的现有会话并验证；用户自行扫码/登录。新增持久浏览器环境或新的访问权限，在实际动作前说明范围并由用户具体确认。本设计不授权自动创建 OAuth、获取 Token 或绕过验证。重新登录不改变既有作品归属；发现不同账号/艺人时暂停并要求重新核对映射。

## 长期复用与两个重启试验

目标是长期复用，不承诺永久有效。客户端启动后恢复映射与会话引用，loginState 先为 unknown，直到合法只读验证完成；不能把上次 valid 永久延用。

A. 客户端关闭重开：浏览器不动，核对相同账号/艺人、绑定修订、未完成任务和选择仍在；另测未登录、过期和错账号。
B. 浏览器关闭重开：独立验证获准持久环境是否保留登录，以及平台是否要求重新验证。A 通过不代表 B 通过；两者都通过也不代表永久有效。

本轮未新建真实登录环境或凭据，因此 A/B 的真实外部会话持续性均是待验收，不能用 fixture 冒充。

## 中断恢复

上传前核对 task 冻结的平台、账号、艺人、绑定修订和当前会话身份。绑定已撤销、登录过期、身份不匹配或无法观察时，仅阻塞此账号后续发布。

| 中断位置 | 重新登录后允许的操作 |
|---|---|
| 尚未开始上传，且可证明无外部操作 | 同一任务、原冻结路由重新核对后继续 |
| 已上传但尚未提交 | 只读核对原草稿/音频与素材指纹；有准确回执才续原稿 |
| 提交已发出，结果未知或客户端重启 | 进入 reconciliation_required，先核对远端原任务；禁止新建上传或重复提交 |
| 已有明确远端提交回执 | 只更新审核状态，不能重提 |
| 身份已变或没有可靠原任务读回能力 | 停止并显示具体阻塞，不伪造成功，不自动重传 |

“重试下载”“继续原稿”“重新登录”“重新提交”必须分开。解除绑定只撤销未来使用，保留作品和在途证据；真正解除按实际确认流程执行。目录请求只引用已授权计划修订，不得指定凭据、改变绑定或扩大发布权限。

## 实施与验收标记

既有单实例/进程重启、提交 unknown 不重发和身份作用域保护继续复用。通用账号绑定 UI、可验证远端艺人读取、多账号会话状态及恢复合同需要在三角色生成路由/艺人快照的统一设计内实现，尚未声称完成。

最低测试：两个账号互不冻结；绑定与登录各状态组合；同名不同ID拒绝；撤销只影响未启动任务；过期会话不可上传；重新登录同身份可续原稿；错身份阻塞；提交后 unknown 重启只对账且新增上传/提交次数为零；客户端/浏览器重启证据分别存档。真实平台能力未具备时报告未接入。
