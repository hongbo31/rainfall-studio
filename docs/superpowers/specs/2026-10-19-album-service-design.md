# 专辑服务接通设计

目的：在既有计划、作品、账号和 TME 发布工作流上完成专辑查询、选择、新建、追加的代码路径，并明确离线通过与线上可用的区别。用户授权继续实现，要求本轮后台、不弹窗、不真实写入、不修改正式入口或既有作品/配置。

## 已核实的起点

已有专辑精确标题＋歌手选择、追加歌曲的准备/提交/回执算法存在；生产端因真实契约和专辑 ID 绑定不足关闭。完整专辑查询、新建远端专辑、持久专辑目录与 Main/Core 消费接口尚未实现。旧 `save_album` 只有本地材料快照，不是新建远端专辑。其他平台没有已验证专辑执行器。不能把这些都归为缺登录。

## 采用的方案

增加独立专辑目录、绑定和操作账本，复用 SQLite settings 分区，不改旧表或用户作品。Main 解析当前平台/账号身份，持有浏览器 transport，Core 校验账号指纹、目录时效、计划意图及素材指纹。现有 TME 追加仍走原准备/条款/提交/回执，不能另造绕过法律确认的上传通道。

目录项区分远端 ID 与本地候选 key。可见候选没有已观察 ID 时可展示，但不能冒充有 ID 的专辑绑定；已知官方歌曲记录中的 albumId 只形成部分目录，不能声明全量。目录保留来源、完整性、观察与过期时间、证据哈希和账号。

新建使用独立浏览器合同执行器：只接受 Main 提供的、校准过的 origin/routes/字段/创建动作/结果 ID 读回契约；生产默认契约为空并给出缺少校准原因。代码必须真实执行“填字段→一次创建→读回 ID”，不能用 stub 成功代替。fixture 通过必须保持 fixture 来源。不得猜官方 API、DOM 或将界面名称变成远端 ID。

## 操作规则

- scope 为 platform/accountId/accountFingerprint；QQ/酷狗同一 TME account family 的专辑意图冲突必须阻塞，不能重复创建。
- 新建先独立持久化 operationId/idempotencyKey/requestHash，再调用 transport；不得在 DB 事务中等待异步写入。
- 相同请求复用操作。dispatching 重启变 unknown；unknown 只能查询原操作，不重发创建或追加。
- 成功必须有同 scope 的远端 albumId，追加还需歌曲回执。fixture 结果不投影为线上验证成功。
- 绑定后的任务使用局部 metadata overlay；不改 Work 或全局平台配置。准备时重新验证相同 overlay。
- 账号、目录、计划快照或素材变化使旧授权失效；停止后仍可保存原回执，但不发新写入。
- public API 只接受账号选择、刷新/选择目录、操作预览和明确确认；原始证据、合同和任意结果录入只留 Main 内部。

## dot 与交付

独立协议文档记录 immutable requests、v2 echo、Drive incoming、receipts、固定本机路径与历史验收边界。当前新版本的请求出口没有线上读回证据时直说；旧 v1 收件成功不算 v2 出口已验证。设计与截图保存至 Library，小文件先交付。

## 验收

真实 Core/Main/浏览器类配隔离响应，覆盖查询/ID 缺失/选择/新建/追加到账、账号与 family 冲突、过期、停止、重启 unknown、重复执行和局部 metadata。所有本轮外部写入均为 fixture，禁止真实登录、平台变更、条款接受或发布。最后报告每项“代码未实现 / 代码已实现但缺真实合同 / 仅缺线上会话验证”的具体状态。
